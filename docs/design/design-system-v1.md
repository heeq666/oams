## 3. 圆角：按元件尺寸分档（2026-10-27 定稿，学苹果）

一句话：**容器 26、中等块 18（含输入框 / 下拉 / 文本域）、行与高亮 9、方框 4；999 是胶囊形状，不算档。**

| 圆角 | 令牌 | CSS 变量 | 用在哪 | 这一层的内距 |
| --- | --- | --- | --- | --- |
| **26** | `radius/card` | `--r-card` / `--wh-radius-card` | 容器：卡片、面板、弹窗、**外壳浮层**（账号菜单 / 开发模式菜单）、空状态、骨架卡 | 16 |
| **18** | `radius/control` | `--r-control` / `--wh-radius` | 中等块：**输入框 / 下拉框 / 文本域**（卡片里的二级控件）、分段控件外框、组织导航、提示条、模块块、字段行、紧凑容器（指标卡）、**卡片里拉出的浮层**（下拉框展开层、卡片内菜单） | 12 |
| **9** | `radius/lg` | `--r-small` / `--wh-radius-sm` | 行与高亮：菜单行、表格行内文本按钮、chip、分段的段、骨架条、侧栏行、卡片里的行高亮 | 8 |
| **4** | `radius/xs` | `--r-micro` / `--wh-radius-micro` | 方框：复选框/单选（16px 见方）、色标、焦点环 | 4 |
| **999** | `radius/pill` | `--r-pill` / `--wh-radius-pill` | 胶囊**形状**（不算层级）：按钮（30 高）、**搜索框**、20 高徽章、开关轨与圆钮、进度条、页码 | — |

用法四句：

1. **按尺寸不按层级**（苹果的做法）：容器 26 → 中层块 18（控件在这里）→ 行与高亮 9 → 方框 4。控件（输入框、下拉、文本域）走 18 而不是 9：它们都长在卡片里，是二级元件。**30 高的盒子上 18 会被浏览器截到 15，渲染出来就是胶囊形** —— 这是 2026-10-28 用户确认要的效果；但值写 18 不写 999，因为高度一变（textarea 120、登录框 44）它就回到真正的圆角矩形。
2. **控件基准线 30**：输入框、下拉、按钮同高 30（40 → 36 → 30，2026-10-27 降到位），顶栏导航胶囊也是 30；高度一律靠 `height`，不靠 padding 凑（曾用 padding 9/12 算出 36 与 35.5 两种高度）。
3. **胶囊按形状走**：高度 ≤ 30 的可点条块取 999 就是半高胶囊；徽章 20 高、页码 30×30、开关轨直接 999。控件（输入框 / 下拉 / 文本域）不写 999 —— 它们写 18，在 30 高的盒子上被截到 15，同样得到胶囊形；高度一变（textarea 120）就自动回到圆角矩形，这正是写 18 而不是 999 的原因。
4. **表格本体 0**：行与行靠 hairline 分隔，与 Figma `140:3902` / `140:4194` 一致；`radius/md`(8) 与 `radius/xl`(14) 是历史变量，新代码不用。

**连续曲率只是 Figma 的**：全库 1417 个圆角节点开了 `cornerSmoothing 0.6`，转角从纯圆弧变成苹果那种连续曲率（半径一个都没改）。CSS 没有对应属性，代码保持圆弧——这是唯一允许「图纸比页面柔和」的地方；真要页面也连续曲率只能 `clip-path` 或 SVG 蒙层，会连带重做边框与焦点环。

**唯一要记的坑**：26 的容器里放 9 的行，内距必须 ≥ 16，否则行的高亮圆角会咬住容器圆角（下节给推导，日常不用算）。

### 3.1 附注：上面那张表为什么成立（贴边内层的角缝不许比边缝窄）

设外框圆角 R、内距 p、内层圆角 r。沿 45° 量，**角上的白缝 = √2·[p + (r − R)(1 − 1/√2)]**，边上的白缝 = p。令两者相等，解出 **r = R − p**（就是同心公式）：

- `r = R − p` → 角缝 = 边缝，两圈弧线同心，最干净；
- `r < R − p` → **角缝比边缝窄**，行高亮看起来咬在外框圆角上，首行/末行最明显；
- `r > R − p` → 角缝比边缝宽，两圈弧线各走各的，也怪。

所以要**加大内层圆角**（或加大内距），不是减小它。第一版按「内层 = 外层 − 2 × 内距」把内层调小，肉眼完全看不出变化——那正好把角缝从 4.7 缩到 1.4，方向反了。

| 外层 | 内距 | 内层 | 角缝 / 边缝 | 用在哪 |
| --- | --- | --- | --- | --- |
| 26 | 16 | 9 | 15.6 / 16 ✓ | 账号菜单、外壳菜单面板、卡片里的行高亮（行 30～32 高） |
| 18 | 16 | 9 | 角部更圆，无缺口 | **卡片里拉出的浮层**（`.wh-list` 下拉展开层）：同心解是 2，实际行圆角 9 比它大，所以不咬角 |
| 18 | 8 | 9 | 7.6 / 8 ✓ | 分段控件的段、控件里贴边的 chip |
| 18 | 4 | 4 | 4.7 / 4 ✓ | 小控件里的内嵌小块（复选框方块） |

行高 30～32 时内层圆角会被 CSS 截到 15/16（`min(r, h/2)`），所以「26 弹层 + 内距 8 + 行 12」算不出同心解（角缝 4.7 对边缝 8，就是咬角的来源）。出路只有两条：内距加到 16，或把弹层降一档。

硬拦截：**贴边块（内距 ≥ 8）出现 `r < R − p` 就是错**，改成加内距或向上取档。不适用的情况有两类：内距 ≤ 4 的紧凑控件（如实测已改的 `.seg`：外框 20 + 内距 8 + 段 12，正好同心）；以及不贴边的独立件——`.flowstrip` 的浅底条里那些阶段胶囊是独立按钮，按自己档位走（999 不受此约束）。

**日常不用算这个公式**：§3 的五个数已经把它解完了（26/16/9、18/8/9、18/4/4），只有新造一种「贴边高亮」时才回来验一遍。

### 5.1 图标：一律 Lucide（2026-10-29 定）

**所有图标用 [Lucide](https://lucide.dev)（ISC 许可，可商用），不手画、不混别家库、不拿 Unicode 字符当图标。** 口径三句话：

- **几何照抄上游**：24 网格、`stroke-width: 2`、`stroke-linecap/-linejoin: round`、`fill: none`。不调锚点、不挪点位、不改描边粗细；显示尺寸缩小靠缩放，不靠改 path。
- **颜色靠变量**：Figma 里描边绑 `text/muted`（需要深色时实例覆盖成 `text/primary` / `accent/on`）；代码里 `stroke="currentColor"`，颜色由父级 `color` 决定。
- **两处同源**：Figma 组件库 `图标 · Lucide（ISC）`（`224:14183`，页面 `02 · 组件 Components`，协作室分区）与模板里的内联 `<svg>` 用同一份 path，改一处必须改另一处。

现在用到的九枚：

| 语义 | Lucide | 用在哪 |
| --- | --- | --- |
| 协作室入口 | `message-circle` | 右下角 48 圆按钮（20 见方，描边 `accent/on`） |
| 收起 | `chevron-down` | 面板右上角、窄屏返回条（18 见方） |
| 展开到顶 / 还原 | `chevrons-up-down` / `chevrons-down-up` | 面板右上角同一按钮两态 |
| 通讯录 | `users` | 左栏搜索带子右侧，切到通讯录之前 |
| 会话 | `message-square` | 同上，切到通讯录之后（两态换图形，不只换底色） |
| 返回 | `chevron-left` | 窄屏对话头 |
| 搜索 | `search` | 搜索框（替掉了原来当图标用的 `⌕` 字符） |
| 关闭 | `x` | 群头右侧 |

为什么定这条（2026-10-29 那轮的真实原因）：协作室最初九枚图标全是按 24 网格手写的 path，结果是描边 1.4 / 1.7 混着用、同一个对话气泡画了两个版本、Figma 与代码各画一遍不完全一致；搜索干脆用的是 `⌕` 字符——笔画跟着字体走，有的系统直接渲染成方框。换库不是「好看一点」，是**把几何交给上游、把我们的判断收回到语义上**。

同一条也适用于字符图标：`⌄` `⤢` `‹` `✕` `⌕` 这类字符在 13–14 号正文旁边又小又虚，字重不可控，缺字时还会退化。需要图标就用图标组件，不要写字。

协作室（`148:7054` 两栏面板，浮层，走 §7.3 的面板状浮层：`bg/surface` + 唯一投影 + `radius/card`）：

- **它是全局的讨论层，不是导航项**：不新增顶级菜单，全站只有右下角一颗 48 圆的按钮（`146:4418`，右下 24 边距）呼出。协作室是独立的一层，**和当前停在哪个页面无关**——左栏会话列表就是全部会话，不分「本页群 / 其他群」。
- **形态 = 一条 52 高的额头 + 底部两栏**（2026-10-29 改）：铺满主区宽、从底边升起，**上两角 28 下两角 0**（贴窗口底边）。额头只有一条 52：**左半是搜索框、右半是群标题**，两段并排在同一行、各自带一条下边线，视觉上连成一条横线。以前是面板头 48 + 对话头 52 上下两层「双额头」，白白压掉 100 的消息区高度，顶上还并排两个标题。下面是主体：左栏会话列表 264 定宽（`bg/subtle`，按「管理群 / 汇报群 / 私聊」三段分组），右栏对话自适应、最窄 520。窗宽 < 900 时只留一栏，列表与对话轮流铺满，对话头出现「‹」返回。
- **左栏有两个视图，用左栏顶部的一枚图标切**：会话视图（默认，群 + 私聊）与**通讯录视图**。图标（`149:10702` 两态，20 见方；两态换的是图形不只是底色——默认画「人 + 两道横线」表示去哪儿，进了通讯录画对话气泡表示回哪儿）落在搜索带子的右侧（2026-10-29 前在面板头标题右侧——那条 48 的面板头已经撤了，位置跟着搬进搜索带子）。切到通讯录时左栏换成「搜索框 + 部门管理员 / 同事两组 + 成员行」（`149:10136`），搜索框占位改「搜同事」、只在这一栏里过滤姓名与「部门 · 岗位」；右栏换成「通讯录」群头 + 「N 位部门管理员 · M 位同事」，还没点人时下面只留一句「私聊只有你们两个人看得到」——人数已经在群头上，不再复述「点谁就跟谁私聊」。**这是发起私聊的唯一入口**：不新增导航、不新增浮层；另一条路是点群聊里某个人的头像。
- **视图状态记在左栏那一层，不记在服务端**（2026-10-29）：左栏只有一个容器，装会话或装成员；`data-collab-view` 是唯一真相，搜索框用一个隐藏字段把它带上。**右栏换内容时不顺手刷左栏**——在通讯录里点开一个同事，回来还是通讯录（早先右栏会连带把左栏刷回会话列表，等于点个人就被弹出通讯录）。图标那枚按钮的 `aria-pressed` / `aria-label` / `title` / 图形跟着两态切（读屏不能永远只会说「通讯录」），选中给白底深图标：左栏底子本身就是 `bg/subtle`，悬停和选中都不能再用 `subtle`，否则看不出按没按下。
  切视图是**纯本地动作**（2026-10-29 改）：会话与通讯录两份列表都随面板一起下发，切换只翻 `data-collab-view`，显隐交给 CSS，右栏空态同理两块都在。原来切换要往 `/collab/side` 取一次，本地回包约 240ms——点下去到列表换掉之间近半秒还是旧内容，看着像没反应。搜索仍走服务端，但 `hx-target` 跟着视图指到当前看得见的那一份（`#collab-thread-list` / `#collab-directory`），不再整栏重取。代价是面板首包多一屏成员行；换来的是切换零延迟。
- **两组按授权分，不按岗位名分**：能改别人进度的人（`workforce.*` 的 manage，与 `admin_level` 同一份清单）进「部门管理员」，其余进「同事」。岗位标题谁都能写成「负责人」，能不能动别人的东西只有授权说了算。通讯录也**不按 `workforce.members:read` 卡**——那条权限管的是改人（工号、岗位、授权），这里只露出姓名 / 部门 / 岗位三样本来就挂在组织架构上的东西，否则只有页面权限的人连同事都找不到。
- **通讯录只排除自己与离职**，说过的私聊把未读挂回人身上（从通讯录点进去和从会话列表点进去是同一个数）；没说过话的走「取或建」，点开这一刻建线程。所以通讯录里不区分「聊过 / 没聊过」。
- **通讯录分片发，一窗 20 行**（2026-10-29 加）：首包只带第一窗 + 一条「加载更多」，滚到它露头再取下一窗（`/collab/side?view=directory&offset=20&after=peers`）。三条口径：① 分组标题由 `after` 接力——上一窗最后一行属于「同事」，下一窗的第一行就**不再画一次「同事」**，否则滚动加载处会冒出第二个分节；② 右栏那行「N 位部门管理员 · M 位同事」是**全公司计数**，不跟着窗口缩，首包只发 20 行也不影响它；③ 点开一个私聊之后左栏会重取一次（为了把未读抹掉），重取带 `limit=已经滚出来的行数`，**不把人滚到一半的名册缩回首包那一窗**。搜索照旧走服务端，过滤之后的名册再按窗切——「搜一个词再往下滚」滚的是搜索结果。
  哨兵**不用 htmx 的 `revealed`**：1.9.12 把「尺寸为 0」也算露出来了，藏在 `display:none` 那一栏里的哨兵会在面板一打开就一路把整份名单拉完（实测 61 人连发三次请求）。改用 `base.html` 里自己的 `IntersectionObserver`（root = 左栏那个滚动容器），隐藏时面积为零、不产生交集；键盘用户也能直接点那一行。
- **未选会话时右栏是空的**（`149:10707`）：只一句「还没选会话」+ 一行「从左栏选一个群或同事」，不自动选中任何会话——协作室是全局层，没有「上次停在哪」的概念。空态下右栏顶上仍留一条**空的群头**（只有下边线、不装内容），否则那条横线会在右栏断开成两截。
- **面板的名字「协作室」降到左栏底部当脚注**（2026-10-29）：它是这一层的名字，不是操作区；占着顶部只会跟搜索框抢那 52，而人找这一层靠的是右下角那颗按钮，不是这条标题。脚注只有一行：「协作室」13 Semibold + 右侧「共 N 条未读」11 muted。**不再挂「全站的讨论层，和你停在哪个页面无关」那句副标题**（2026-10-29 删）——同样的意思空态里已经说过，两处一起出现就是自己跟自己重复。
- **三类会话**：管理群（部门管理员之间，谈「这页该不该长这样」）、汇报群（填这页的岗位 + 部门管理员，谈「这格填什么」）、私聊（两个人之间，答疑与口径澄清用）。私聊头像走**圆形**、群头像走**圆角 9 方块**——形状和图标双重区分对话还是群；但两者**都是 `bg/surface` 白底 + 1px `border/default` hairline**（群头像曾经用 `bg/subtle` 底，而左栏底子本身就是 `bg/subtle`，于是群的图标看上去「没有底」、私聊有底，同一列两种待遇），不用再从群名首字里猜（「设计部 · 管理群」和「设计部打样进度 · 汇报群」取首字都是「设」）。消息区每条消息左侧的头像同理，一律 `user`：说话人是谁由名字和 AI 徽章说，不靠头像里的一个字。私聊同样**不授予任何权限**，只是两个人的对话。
- **会话行 264×56，三态走令牌**：默认无填充（透出左栏 `bg/subtle`）、悬停 `fill/hover`、选中 `bg/surface`。头像 32（两者都是 `bg/surface` 白底 + 1px `border/default` hairline、里面一枚 18 的图标 `text/secondary`；形状区分：群 = `radius/lg` 方块 + `users`，私聊 = 圆形 + `user`）+ 名称 13 Medium + **最后一条消息** 12 `text/muted` 截断（没有消息时这一行不出现，只有名字，垂直居中）+ 右侧时间 11 / 未读 16 圆 `status/danger`。第二行**只放真实的最后一句**，不拿「部门管理员在这里讨论页面怎么搭」这类模板句占位。**群与私聊只靠头像形状区分，不新增第二个语义色**。
- **三档宽度，跟着视口走，靠右边停**：宽屏 1313（1440 档，与 Main 左右都对齐）/ 紧凑 960（1024 档）/ 单栏 704（768 档）。一律**右边缘贴视口右边**（`right: 0`，宽度 `100vw − 64`），不是水平居中——按钮在右下角，面板却从屏幕正中间升起来，视线得先跑一趟；贴右边才是「从按钮那儿长出来的」。超宽屏（> 1377）封顶 1313 后仍然贴右，左边缘留在 607 而不是跟着居中。

- **发言人标注 = 用户名 + 模型名**：AI 代发时在人名后跟一枚 `model` 变体徽章（写 Codex / WorkBuddy / Claude…），本人发言不带徽章。走**浅紫底紫字**：`data/agent-subtle` 底 + 1px `data/agent-line` 描边 + `data/agent` 紫字，高 20、`radius/pill`。不用实心紫底——徽章的视觉重量不该超过它标注的正文（一屏 3 枚实心紫块会把消息压下去）。不复用「AI 代笔」这四个字当发言人标签——看板上「AI 代笔占比」是统计口径，两者别混。
- **加载更早就在消息区顶部**（`148:9391`，2 变体）：往上滚到顶自动拉下一批，出现「正在加载更早的消息…」（12 号 `text/muted`，居中等宽，不加底色与按钮边框）；全部拉完换成「已经是最早的消息了」，之后不再有动作。**不做整页历史**——协作室永远只装最近的一批，要长历史就是另一个形态，现在不画。
- **搜索框搜三样东西、走跳转不走筛选**（`172:11637` 视图=搜索）：占位统一「搜索会话、消息、同事」，结果按「消息 / 同事 / 会话」分组列，每条结果是一块搜索片段（`173:11978`，状态=默认 / 选中：上面 11 号 `text/muted` 写来源，下面 13 号 `text/secondary` 写命中片段，选中给 `bg/surface` 底）。**搜索框不是筛选器**——左栏不会一边打字一边把会话列表过滤成两行，那会跟「左栏 = 全部会话」打架，员工会以为群没了；而且筛选天生只能筛会话，搜不到消息内容与同事。点一条结果才进那个群，并把命中的那条消息滚到视野里，用一圈 `bg/subtle` 的**定位高亮**（`173:11980`，圆角 9、比消息四周各外扩 8/4）标出来：不闪烁、不自动消失，直到你发下一句话或切走会话。
- **@ 提及是两处标记，不是一种底色**（`172:11459` 提及点）：被 @ 的那条消息左侧一条 2 宽 `status/danger` 竖线（贴消息左边距），对应会话行的头像上角一枚 8 的点（同色底 + 2px `bg/surface` 描边）。会话行**不因为被 @ 就变底色**——底色只表示选中。头部的未读汇总是总未读，@ 不另外计数：一枚徽章只说「有多少条没看」，说不到「哪个群被 @ 了」，那件事点开就看到。
- **点结果后左栏保持搜索结果**：不自动切回会话列表——找东西常常连着找几处，切回去就得重新打字。代价是左栏与右栏会短暂对不上（左边是结果、右边是某个群），这是故意的；清空搜索框或按对话头的「‹」才回到会话列表。
- **日期分隔只在跨天处插**（`172:11526`）：一条「10月25日」，两侧各一条 1 高 `border/default` 细线，中间 12 号 `text/muted`，整条不占底色、不可点。同一天连续消息之间不插。
- **消息只能发，不能编辑也不能撤回**：不做长按菜单、不做「已撤回」占位、不做 2 分钟窗口。发错了就在下一条说清楚——协作室是讨论层，不是档案库，改历史比留一条错的更容易让人读岔。
- **消息区的两个状态只换消息区**（`173:11988` 视图=空会话 / `173:12150` 视图=加载失败）：群头、左栏、输入框的位置一律不动，别让整块面板跳。① 空会话 = 消息区居中放 `140:3804` Empty 实例，文案随会话类型变（2026-10-29）：群「这个群还没人说过话」+「说第一句话，管理员和填这页的同事都看得到」、管理群「…部门管理员都看得到」、私聊「还没说过话」+「发第一句吧，只有你们两个人看得到」——**空态的职责是说清「这句话谁看得见」**，私聊不是群，不能套群的文案。**输入框照常可用不藏**——空群也要能说话。② 加载失败 = 同一块位置换成危险 Alert（「消息没取到」+「网络断了或会话已失效，重连后再试。」）+ 次要按钮「重新加载」，输入框禁用置灰。空态不用插画，失败态不用 toast——toast 会飘走，而「取不到消息」是要停在那儿解决的。
- **输入区没有上边框**（2026-10-29）：输入框本身就是一个 40 高的描边胶囊，已经把它和消息区分开了；再加一条通栏细线就是两层分界，白的消息区被切得零碎。上内距压到 4，让输入框往上贴近消息区。
- **输入框会往上长，失败的消息原地留着**（`172:11629` 两变体）：单行 40，超过一行往上长，三行（88）封顶后内部滚动；发送按钮始终在右侧垂直居中。发不出去的那条右侧、时间左边一枚 16 的 `status/danger` 感叹号（`172:11524`，1.2 描边圆），**消息本身不褪色、不位移**——失败的正文要能原地选中复制。点那枚图标才重发，不做自动重试。
- **未读只有一份，存在服务端**（`146:4418` 状态=未读）：点开一个会话就算这个群全读完，徽章立刻清零并写回，换设备换浏览器看到的是同一个数；不做实时推送，下次拉取时对齐即可。自己发的那条永远不算未读。**点开即清零、不画「以下是新消息」的分界线**——切走就当看过，漏了的自己往上翻。徽章只给一个总未读数、不说哪个群（用户 m02271 定：不画新消息分界）。
- **不做「采纳到页面」**：协作室只讨论、只解决口径互通，真改页面回员工自己的 AI 软件里做。留一个「转成条目」的入口，协作室就会长成车间入口。
- **九枚图标全部换 Lucide，字符图标清零**（2026-10-29）：协作室原来拿 `⌄` `⤢` `✕` `‹` `⌕` 当图标、入口按钮和通讯录入口各手画一份气泡，笔画粗细在 1.4/1.7 之间混着用，同一家还画出了两个不完全一样的版本。现在一律按 §5.1 走 Lucide（24 网格、stroke 2、圆头圆角）：入口 `message-circle`、收起 `chevron-down`、到顶/还原 `chevrons-up-down` / `chevrons-down-up`、通讯录 `users`、会话 `message-square`、返回 `chevron-left`、搜索 `search`、关闭 `x`。Figma 组件库在 `图标 · Lucide（ISC）`（`224:14183`，9 个 24×24 组件），模板里内联同一份 path。**不再出现「用文字当图标」**：字号跟着正文字体走，13 号旁边又小又虚，缺字时还退化成方框。

- **文案只写对方不知道的事，不解释已经看得见的东西**（2026-10-29 用户定：「优化下这种没必要的说明文字，用户有脑子的」）：分组标题只写「管理群 / 汇报群 / 私聊」，后面不跟「管理员之间谈页面怎么搭」这种把组名换个说法再讲一遍的说明；会话行第二行只放真实的最后一条消息，不放模板句；群头标题不再重复类型（类型由旁边那枚徽章说，标题里写「设计部打样进度」而不是「设计部打样进度 · 汇报群」，左栏没有徽章的行才带后缀）；同一句话只在一个地方出现一次（「全站无关当前页面」以前空态和脚注各说一遍，删掉脚注那句）。判断标准：删掉之后读者是否还知道该干什么——知道就删。
- **未读徽章固定 16 高**（`146:4413` / 会话行右侧 `未读数字`）：`min-width: 16`、左右内距 4、`radius/pill`、11 号 **Medium**、`status/danger` 底 + `text/inverse` 字，文字 `textAutoResize = WIDTH_AND_HEIGHT`。**不给 minWidth 的 HUG 徽章会被挤成 7×16 的窄椭圆**（2026-10-28 踩过：`148:6354` / `148:8506` / `172:11856` 三个变体就是这样）。位数决定宽度：一位 16、两位约 20、「99+」约 28（浏览器实测 `1`→16、`12`/`99`→20、`99+`→27，差 1px 是字体亚像素），一律 HUG 不写死、别写死宽度。**超过 99 一律显示「99+」**（用户 m03468 定），不写三位数：徽章是 16 高的圆点，真实条数另有去处——`aria-label` 写「未读 N 条」、面板头写「共 N 条未读」，徽章只负责一眼看出「有多少没看」。徽章里只放数字，不放「条」「新」这类字。
- **带白环的小圆点一律用 OUTSIDE 描边**（入口按钮的未读徽标 `146:4413`、@ 提及点 `172:11459`）：INSIDE 描边会从直径里抠掉两倍描边宽——16 的红徽标只剩 14、8 的提及点只剩 4×4，视觉上像掉了一半。**白环画在外面**：入口徽标 1.5 OUTSIDE `bg/surface`、提及点 2 OUTSIDE `bg/surface`，红区保持完整 16 / 8。同理，徽标里如果塞了文字，文字节点的 `textAutoResize` 必须是 `WIDTH_AND_HEIGHT`——写成 `HEIGHT` 会让父帧按 17~18 算宽，位置跟着漂。

- **入口按钮不遮挡任何东西，弹层升起时它自己让位**：按钮 48 圆、`right: 24px` / `bottom: 24px`、`z-index: 60`。开发模式的身份切换角标原来也在右下角，现在让到按钮左边（`right: 84px` = 24 + 48 + 12 间隙；`bottom: 34px` = 24 + (48−28)/2，让 28 高的角标与 48 圆同心）。面板升起后按钮改 `opacity: 0` + `pointer-events: none`——1440 下面板右边只留 63px，768 下整宽盖住，按钮不藏就会被面板压住。
- **两枚图标按钮 32 见方、图标 18 见方**（2026-10-29 从 28 / 14 号字符放大）：以前 `⌄` `⤢` `‹` 是直接打的字符，字重和笔画跟着字体走，跟旁边 13 号正文摆一起显得又小又虚，也确实不到 `.btn-sm` 的 32 档。改成定长 SVG 后三条线一个粗细（1.7 描边、圆头圆角），大小可控。**到顶 = 上下双向箭头朝外、还原 = 两支箭头朝中间收回**：面板本来就是一条竖直的带子，竖直箭头就是它长大的方向；斜角方框（`⤢` 那类）在小尺寸下认不出是「放大」还是「跳到新窗口」。同一按钮两态，换图标不换位置，`aria-pressed` / `aria-label` / `title` 跟着切（读屏不能永远只会说「展开到顶」）。
- **收起按钮只有一个，在面板右上角**：它**不能挂在左栏里**——一个会话都没选（右栏是空态）的时候，左栏那枚 ✕ 落在画面偏左，人往右上角找会扑空；挂在左栏还有个副作用：左栏只有 264 宽，压根不是「右上角」。对话头里不再放任何图标，只留「‹ 返回」（窄屏）。
- **弹层没有遮罩，点到面板外面就收起**：它不是模态框，只是从底边升起来的一层，页面照常可见可滚——正因为底下那半页仍然可点，人在那种状态下按页面就是在说「我看完了」，不该再要求他去右上角找 `⌄`。三路关掉：右上角的 `⌄`、Esc、点面板外任意处（监听 `mousedown` 而不是 `click`，按下即收，免得拖选文字时先收起一半）。**没有遮罩，所以这三路必须各自都在**：少一路，那半页就成了「点了会误触进去却关不掉」的陷阱。
- **窄屏只有一个切换类 `is-thread`**：面板不加 `is-thread` → 只显示左栏（会话列表铺满）；加了 → 只显示右栏（对话铺满，对话头出现「‹」返回）。不要写成「默认留左栏 + 反过来加类显示左栏」那种双向开关，两个方向的默认值会打架。宽度只由一条公式算：`min(1313px, 100vw − 64px)`，窄屏不再另设（`@media (max-width: 899px)` 只管切单栏）；`prefers-reduced-motion` 下关掉升起动画。
- **输入框的 40 / 88 是局部口径，不是全局控件口径**：外壳里 `textarea` 的公共规格是「最小高 120、内距 10/12」（`base.html:429`），协作室的输入框必须显式压回 24 行盒起步——`min-height: 24px`，超过一行往上长，到 88（三行）封顶后内部滚动。发送按钮与输入框**垂直居中**，靠 `align-items: center` + 1px 上下内距 + 36 圆按钮凑出 40 高；写成 `flex-end` 时按钮会掉到底边。
- **消息贴输入框排，不贴顶**：一两条消息时消息区顶部会露出一大片空白（Figma 里是 `primaryAxisAlignItems: MAX`）。CSS 侧用一条 `flex: 0 0 auto; margin-top: auto` 的伪元素占位顶上去，别用 `justify-content: flex-end`——内容超高时 `flex-end` 会把顶部裁掉、滚不到最早的消息。打开会话即滚到底，切会话也滚到底。
- **「加载更早」是替换那一行，不是重画整个消息区**：加载行自带 `id="collab-before"`、`hx-target="this"`、`hx-swap="outerHTML"`，历史消息 prepend 在它下面；`htmx:beforeSwap` 记下 `{scrollTop, scrollHeight}`，`afterSwap` 按高度差把 `scrollTop` 补回去，视线原来那条不被顶走。滚到顶自动触发（`scroll` 不冒泡，监听要挂 `capture`），全部拉完后加载行换成「已经是最早的消息了」并不可再点。
- **开合状态挂在 `<body>` 上，不能挂在 htmx 的 swap 目标上**：`#collab-host` 是 htmx 的替换目标，htmx 会改它的 `className`（`htmx-settling`），挂在上面的 `is-open` 会被抹掉，面板升不起来 / 升起来关不掉。规则：`body.collab-open` 控制升起，脚本里用`wantOpen` 一个变量做唯一真相（`reveal()` 读它、`close()` 清它），按钮与 Esc 都只改它。

> 分层判断：**骨架层** = 页面外壳（一页一套，全站复用）；**组件层** = 卡片 / 面板内部用的控件与数据件；**浮层** = 浮在整页之上的东西；**协作室** = 右下角圆按钮呼出的全局讨论层；**模块层** = 与 `MODULE_REGISTRY` 对齐、由容器 + 组件拼成的内容块。新组件先判断属于哪一层，再进对应分区。

## 7. 八条硬规则

1. **只用令牌**：颜色、圆角、间距、字号一律引用变量/`--wh-*`，不写字面值。
2. **不发明圆角**：五档里挑一个 —— 方框 4、行与高亮 9、中等块 18（含输入框 / 下拉 / 文本域）、容器 26、胶囊 999；表格本体 0。挑不到就说明该加组件，别加圆角。
3. **内容实色、浮层玻璃**：页面里的卡片 / 表格 / 面板靠底色差与 1px `border/default` 分层，**不加投影、不加模糊**。凡是浮在内容之上的一层——顶栏胶囊（含静止态中间那颗导航胶囊）、账号菜单、开发模式身份菜单、下拉框展开层、Menu、Tooltip——一律「**本体玻璃**」，只有这一套：

   ```css
   /* 条状浮层：顶栏胶囊、导航胶囊 */
   background: rgba(255, 255, 255, .70);
   backdrop-filter: saturate(1.2) blur(10px);
   box-shadow: 0 4px 12px -2px rgba(15, 23, 42, .10);   /* 唯一的投影，别加第二层 */

   /* 面板状浮层：菜单、下拉框展开层、Tooltip —— 白 78% + blur 16，比条状浮层更雾 */
   background: rgba(255, 255, 255, .78);
   backdrop-filter: saturate(1.3) blur(16px);
   box-shadow: 0 4px 12px -2px rgba(15, 23, 42, .10);
   ```

   为什么面板比条状浮层更雾：菜单里要读字，底下正文必须退到雾里，否则两层文字叠在一起谁也读不清；顶栏只承载导航，看得见底下流动的内容才是它存在的意义。两者的投影**同一值**，只差粒度。

   **浮层不能长在 `<details>` 里**（2026-10-26 定，踩过）：账号菜单与身份菜单一度把面板塞在 `<details>` 内部，结果是「菜单透得比顶栏胶囊明显得多」。原因不在数值——`<details>` 是一个 backdrop root，里面的 `backdrop-filter` 只能采样这个 root 内部的绘制内容，拿不到页面背景，玻璃就退化成一层平白，底下的字照样清晰可读。同一份配方挂到 `<body>` 上立刻正常（同一块黑白条纹实测：`<details>` 里条纹残留 p2p 94，`<body>` 上 p2p 4）。所以浮层一律挂 `<body>`、`position: fixed`；触发器只负责「按一下」，面板挂在哪儿、摆在哪个坐标、什么时候收起来，全归**浮层载体** `static/wh-popover.js`（见下）。

   `<details>` 之外，也别把浮层塞进带 `transform` / `filter` / `opacity < 1` / `mask` 的容器：它们同样可能成为 backdrop root，玻璃就只剩一层白。

   **不落遮罩**（2026-10-26 定）：菜单和下拉框底下一度盖过一层 `rgba(10,10,10,.12)` 的薄雾，撤掉了——blur 已经把正文糊开，再压一层灰只会让整页发闷、面板显脏。代价是**「点到别处要关掉」得由脚本兜住**——这一条统一由载体做（document `mousedown` / `Esc` / `focusout` / `scroll` / `resize` 五路），加新浮层不用重写一遍，但**也别把这几路监听删掉**，删了就没有遮罩替你收尾。将来的 Modal 要不要遮罩，等真做时单独定，不要顺手抄菜单。

   圆角按位置取：条状浮层（顶栏胶囊、导航胶囊、徽标胶囊）用 `radius/pill`；面板状浮层分两种——**挂在外壳上的**（账号菜单、开发模式菜单、弹窗、Tooltip）用 `radius/card` 26，**从卡片里的控件拉出来的**（下拉框展开层、卡片行内的 `…` 菜单）用 `radius/control` 18：外层卡片已经占了 26，同一处不重复用容器档（同 §3 的嵌套规则）。浮层不加描边——投影 + 明度差已经够分离，再描边会在玻璃上出现一道硬线。

   上面这些值和 `backdrop-filter` 是**唯一允许写字面值的地方**：玻璃是「叠在什么上面」的效果，不是一种颜色，进不了颜色令牌。要改就几处一起改（见 §8.3 的落点清单），别只改一处。

   **浮层只有一个载体**（2026-10-26 定）：三处浮层原先各写各的——顶栏胶囊是纯 CSS，账号菜单与身份菜单是一段 `wireMenu()`，下拉框是 `wh-select.js` 自带的定位。外观统一了，但**挂载 / 摆放 / 关闭**三件事各做了一遍，加第四个浮层就得抄第四遍。现在只有 `static/wh-popover.js`：

   - **声明式**：触发器写 `data-wh-popover` + `aria-controls="<面板 id>"`，面板写 `class="wh-popover"`。可选用 `data-wh-align`（start/end）/ `data-wh-side`（below/above/auto）/ `data-wh-gap` / `data-wh-min-width` 调位置。载体自动把面板 append 到 `<body>`、置 `hidden`、维护 `aria-expanded`、按视口夹取坐标（8px 边距、下方不够翻上方），htmx 换完内容自动重扫。
   - **长相只有一条规则**：`.wh-popover`（玻璃 + 28 圆角 + 唯一投影 + `--z-popover: 70`）。`.account-menu` / `.dev-menu` / `.wh-list` 只声明宽度与内距，**不许再写 background / box-shadow / backdrop-filter**。
   - **要自己管开关的**（比如下拉框按需构建选项行）用 `whPopover.attach({... , manual: true})` 拿实例，其余一律声明式。
   - **契约有测试**：`tests/test_popover_contract.py` 盯着这条——面板跑进 `<details>`、皮肤被抄第二遍、`wh-popover.js` 下到 `wh-select.js` 后面，都会红。

   目前的落点：顶栏（滚动后的窄胶囊；静止态下玻璃在中间的导航胶囊上，条形本身透明；玻璃做在 `.bar-glass` 这一层上，因为带 `backdrop-filter` 的元素会成为 backdrop root，嵌在里面的下拉就取不到页面背景）、账号菜单 `.account-menu`、开发模式身份菜单 `.dev-menu`、下拉框展开层 `.wh-list`。以后加 Modal / Tooltip / Popover 不要另调一套数值——直接照抄上面，再把新落点补进 §8.3。没有描边的实色面板之间必须留 `space/5`（16px）——两块白面板贴在一起会粘成一整块，26 的圆角还会互相啃出缺口。
4. **一个强调色**：`accent/default` 一屏只出现一次主动作；次要动作走 `secondary`（白底 + hairline）。
5. **状态色只表达状态**：不许拿 `status/danger` 做装饰，也不许拿 `data/agent` 做品牌色。
6. **表格单行**：行高 30（6/8 内距 + 18 行盒 + 1px 分隔线），页面数据表的单元格不折行，超宽用省略号（`text-overflow: ellipsis`），不靠缩字号；模块内明细表在窄栏里可以折行。
7. **控件四态**：每个可交互组件都要有 default / hover / focus / disabled；表格行要 default / hover / selected。
8. **数字优先**：指标数值用 `Display/Metric`，单位小一号且 `text/muted`；金额与数量右对齐。

## 9. 怎么在别的对话里用

三种载体，按复用范围选：

1. **本仓库的会话**：根目录 `AGENTS.md` 已写好入口，任何新会话会自动带上硬规则和本文路径 —— 什么都不用说。
2. **别的仓库 / 别人的机器**：把 `skills/workhub-design-system/SKILL.md` 装进 `~/.dsh/skills/workhub-design-system/`，之后说「按 workhub 设计规范做这个页面」即可。
3. **只想让 AI 读一次**：直接说「读 `docs/design/design-system-v1.md` 和 `docs/design/tokens.json`，按里面的令牌和八条硬规则实现」。

Figma 侧同理：新会话里说「按 `0:1` 页的组件库补一个 xxx 组件」，它会自己读令牌、复用既有组件、写回本页。
