## 3. 圆角：按元件尺寸分档（2026-10-27 定稿，学苹果）

一句话：**容器 26、中等块 18（含输入框 / 下拉 / 文本域）、行与高亮 9、方框 4；999 是胶囊形状，不算档。**

| 圆角 | 令牌 | CSS 变量 | 用在哪 | 这一层的内距 |
| --- | --- | --- | --- | --- |
| **26** | `radius/card` | `--r-card` / `--oams-radius-card` | 容器：卡片、面板、弹窗、**外壳浮层**（账号菜单 / 开发模式菜单）、空状态、骨架卡 | 16 |
| **18** | `radius/control` | `--r-control` / `--oams-radius` | 中等块：**输入框 / 下拉框 / 文本域**（卡片里的二级控件）、分段控件外框、组织导航、提示条、模块块、字段行、紧凑容器（指标卡）、**卡片里拉出的浮层**（下拉框展开层、卡片内菜单） | 12 |
| **9** | `radius/lg` | `--r-small` / `--oams-radius-sm` | 行与高亮：菜单行、表格行内文本按钮、chip、分段的段、骨架条、侧栏行、卡片里的行高亮 | 8 |
| **4** | `radius/xs` | `--r-micro` / `--oams-radius-micro` | 方框：复选框/单选（16px 见方）、色标、焦点环 | 4 |
| **999** | `radius/pill` | `--r-pill` / `--oams-radius-pill` | 胶囊**形状**（不算层级）：按钮（30 高）、**搜索框**、20 高徽章、开关轨与圆钮、进度条、页码 | — |

用法四句：

1. **按尺寸不按层级**（苹果的做法）：容器 26 → 中层块 18（控件在这里）→ 行与高亮 9 → 方框 4。控件（输入框、下拉、文本域）走 18 而不是 9：它们都长在卡片里，是二级元件。**30 高的盒子上 18 会被浏览器截到 15，渲染出来就是胶囊形** —— 这是 2026-10-28 用户确认要的效果；但值写 18 不写 999，因为高度一变（textarea 120、登录框 44）它就回到真正的圆角矩形。
2. **控件基准线 30**：输入框、下拉、按钮同高 30（40 → 36 → 30，2026-10-27 降到位），顶栏导航胶囊也是 30；高度一律靠 `height`，不靠 padding 凑（曾用 padding 9/12 算出 36 与 35.5 两种高度）。
3. **胶囊按形状走**：高度 ≤ 30 的可点条块取 999 就是半高胶囊；徽章 20 高、页码 30×30、开关轨直接 999。控件（输入框 / 下拉 / 文本域）不写 999 —— 它们写 18，在 30 高的盒子上被截到 15，同样得到胶囊形；高度一变（textarea 120）就自动回到圆角矩形，这正是写 18 而不是 999 的原因。
4. **表格本体 0**：行与行靠 hairline 分隔（与表格密度规格一致）；`radius/md`(8) 与 `radius/xl`(14) 是历史变量，新代码不用。

**连续曲率只在图纸上，代码保持圆弧**：图纸里圆角节点设了 `cornerSmoothing 0.6`，转角从纯圆弧变成苹果那种连续曲率（半径一个都没改）。CSS 没有对应属性——这是唯一允许「图比页面柔和」的地方；真要页面也连续曲率只能 `clip-path` 或 SVG 蒙层，会连带重做边框与焦点环。

**唯一要记的坑**：26 的容器里放 9 的行，内距必须 ≥ 16，否则行的高亮圆角会咬住容器圆角（下节给推导，日常不用算）。

### 3.1 附注：上面那张表为什么成立（贴边内层的角缝不许比边缝窄）

设外框圆角 R、内距 p、内层圆角 r。沿 45° 量，**角上的白缝 = √2·[p + (r − R)(1 − 1/√2)]**，边上的白缝 = p。令两者相等，解出 **r = R − p**（就是同心公式）：

- `r = R − p` → 角缝 = 边缝，两圈弧线同心，最干净；
- `r < R − p` → **角缝比边缝窄**，行高亮看起来咬在外框圆角上，首行/末行最明显；
- `r > R − p` → 角缝比边缝宽，两圈弧线各走各的，也怪。

所以要**加大内层圆角**（或加大内距），不是减小它。第一版按「内层 = 外层 − 2 × 内距」把内层调小，肉眼完全看不出变化——那正好把角缝从 4.7 缩到 1.4，方向反了。

| 外层 | 内距 | 内层 | 角缝 / 边缝 | 用在哪 |
| --- | --- | --- | --- | --- |
| 26 | 16 | 9 | 15.6 / 16 ✓ | 账号菜单、外壳菜单面板、卡片里的行高亮（行 30～32 高） |
| 18 | 16 | 9 | 角部更圆，无缺口 | **卡片里拉出的浮层**（`.wh-list` 下拉展开层）：同心解是 2，实际行圆角 9 比它大，所以不咬角 |
| 18 | 8 | 9 | 7.6 / 8 ✓ | 分段控件的段、控件里贴边的 chip |
| 18 | 4 | 4 | 4.7 / 4 ✓ | 小控件里的内嵌小块（复选框方块） |

行高 30～32 时内层圆角会被 CSS 截到 15/16（`min(r, h/2)`），所以「26 弹层 + 内距 8 + 行 12」算不出同心解（角缝 4.7 对边缝 8，就是咬角的来源）。出路只有两条：内距加到 16，或把弹层降一档。

### 3.2 两套变量：外壳一套、模块一套（2026-10-30 记）

项目里同时存在两组 CSS 变量，**两组都是变量、都合规，不算破例**，但它们不是同一套，用错会取不到值：

| 层 | 变量 | 定义位置 | 谁用 |
| --- | --- | --- | --- |
| 外壳层 | `--bg` / `--card` / `--ink` / `--muted` / `--line` / `--accent` / `--blocked` / `--done` 等，圆角 `--r-card` 26 / `--r-control` 18 / `--r-small` 9 / `--r-micro` 4 / `--r-pill` 999 | `app/oams/templates/base.html:223`（`:root`） | 外壳、页面、协作室（`oams-collab.css`）、所有不属于模块渲染的模板 |
| 模块层 | `--oams-*`：`--oams-bg` / `--oams-bg-muted` / `--oams-line` / `--oams-text` / `--oams-muted` / `--oams-accent` / `--oams-info` / `--oams-radius*` / `--oams-gap-*` 等 | `app/oams/static/oams-modules.css:12`（**在 `.wh-interface` 选择器内**） | 只给 `render.py` 渲染出来的模块标记用 |

关键一条：**`--oams-*` 定义在 `.wh-interface` 里面**，所以外壳和协作室挂在它外面时取不到值——那正是它们走 `:root` 那套的原因，不是写死了字面色值。反过来，模块层也不该用 `--bg` / `--r-control`，会随外壳改而漂。新写 CSS 先问一句「这段挂在 `.wh-interface` 里面吗」，答案决定用哪套。

硬拦截：**贴边块（内距 ≥ 8）出现 `r < R − p` 就是错**，改成加内距或向上取档。不适用的情况有两类：内距 ≤ 4 的紧凑控件（如实测已改的 `.seg`：外框 20 + 内距 8 + 段 12，正好同心）；以及不贴边的独立件——`.flowstrip` 的浅底条里那些阶段胶囊是独立按钮，按自己档位走（999 不受此约束）。

**日常不用算这个公式**：§3 的五个数已经把它解完了（26/16/9、18/8/9、18/4/4），只有新造一种「贴边高亮」时才回来验一遍。

### 5.1 图标：一律 Lucide（2026-10-29 定）

**所有图标用 [Lucide](https://lucide.dev)（ISC 许可，可商用），不手画、不混别家库、不拿 Unicode 字符当图标。** 口径三句话：

- **几何照抄上游**：24 网格、`stroke-width: 2`、`stroke-linecap/-linejoin: round`、`fill: none`。不调锚点、不挪点位、不改描边粗细；显示尺寸缩小靠缩放，不靠改 path。
- **颜色靠变量**：规范里描边用 `text/muted`（需要深色时用 `text/primary` / `accent/on`）；代码里 `stroke="currentColor"`，颜色由父级 `color` 决定。
- **两处同源**：本节记的这份图标集与模板里的内联 `<svg>` 用同一份 path，改一处必须改另一处。

现在库里有十五枚（2026-10-30 补 `plus` / `trash-2` / `external-link` / `arrow-right`）：

- **两组按授权分，不按岗位名分**：能改别人进度的人（`workforce.*` 的 manage，与 `admin_level` 同一份清单）进「部门管理员」，其余进「同事」。岗位标题谁都能写成「负责人」，能不能动别人的东西只有授权说了算。通讯录也**不按 `workforce.members:read` 卡**——那条权限管的是改人（工号、岗位、授权），这里只露出姓名 / 部门 / 岗位三样本来就挂在组织架构上的东西，否则只有页面权限的人连同事都找不到。

- **通讯录分片发，一窗 20 行**（2026-10-29 加）：首包只带第一窗 + 一条「加载更多」，滚到它露头再取下一窗（`/collab/side?view=directory&offset=20&after=peers`）。三条口径：① 分组标题由 `after` 接力——上一窗最后一行属于「同事」，下一窗的第一行就**不再画一次「同事」**，否则滚动加载处会冒出第二个分节；② 右栏那行「N 位部门管理员 · M 位同事」是**全公司计数**，不跟着窗口缩，首包只发 20 行也不影响它；③ 点开一个私聊之后左栏会重取一次（为了把未读抹掉），重取带 `limit=已经滚出来的行数`，**不把人滚到一半的名册缩回首包那一窗**。搜索照旧走服务端，过滤之后的名册再按窗切——「搜一个词再往下滚」滚的是搜索结果。

- **搜索框搜三样东西、走跳转不走筛选**（视图=搜索）：占位统一「搜索会话、消息、同事」，结果按「消息 / 同事 / 会话」分组列，每条结果是一块搜索片段（状态=默认 / 选中：上面 11 号 `text/muted` 写来源，下面 13 号 `text/secondary` 写命中片段，选中给 `bg/surface` 底）。**搜索框不是筛选器**——左栏不会一边打字一边把会话列表过滤成两行，那会跟「左栏 = 全部会话」打架，员工会以为群没了；而且筛选天生只能筛会话，搜不到消息内容与同事。点一条结果才进那个群，并把命中的那条消息滚到视野里，用一圈 `bg/subtle` 的**定位高亮**（圆角 9、比消息四周各外扩 8/4）标出来：不闪烁、不自动消失，直到你发下一句话或切走会话。
- **@ 提及是两处标记，不是一种底色**（提及点）：被 @ 的那条消息左侧一条 2 宽 `status/danger` 竖线（贴消息左边距），对应会话行的头像上角一枚 8 的点（同色底 + 2px `bg/surface` 描边）。会话行**不因为被 @ 就变底色**——底色只表示选中。头部的未读汇总是总未读，@ 不另外计数：一枚徽章只说「有多少条没看」，说不到「哪个群被 @ 了」，那件事点开就看到。

- **消息区的两个状态只换消息区**（视图=空会话 / 视图=加载失败）：群头、左栏、输入框的位置一律不动，别让整块面板跳。① 空会话 = 消息区居中放 Empty 实例，文案随会话类型变（2026-10-29）：群「这个群还没人说过话」+「说第一句话，管理员和填这页的同事都看得到」、管理群「…部门管理员都看得到」、私聊「还没说过话」+「发第一句吧，只有你们两个人看得到」——**空态的职责是说清「这句话谁看得见」**，私聊不是群，不能套群的文案。**输入框照常可用不藏**——空群也要能说话。② 加载失败 = 同一块位置换成危险 Alert（「消息没取到」+「网络断了或会话已失效，重连后再试。」）+ 次要按钮「重新加载」，输入框禁用置灰。空态不用插画，失败态不用 toast——toast 会飘走，而「取不到消息」是要停在那儿解决的。

- **两枚图标按钮 32 见方、图标 18 见方**（2026-10-29 从 28 / 14 号字符放大）：以前 `⌄` `⤢` `‹` 是直接打的字符，字重和笔画跟着字体走，跟旁边 13 号正文摆一起显得又小又虚，也确实不到 `.btn-sm` 的 32 档。改成定长 SVG 后三条线一个粗细（1.7 描边、圆头圆角），大小可控。**到顶 = 上下双向箭头朝外、还原 = 两支箭头朝中间收回**：面板本来就是一条竖直的带子，竖直箭头就是它长大的方向；斜角方框（`⤢` 那类）在小尺寸下认不出是「放大」还是「跳到新窗口」。同一按钮两态，换图标不换位置，`aria-pressed` / `aria-label` / `title` 跟着切（读屏不能永远只会说「展开到顶」）。
- **收起按钮只有一个，在面板右上角**：它**不能挂在左栏里**——一个会话都没选（右栏是空态）的时候，左栏那枚 ✕ 落在画面偏左，人往右上角找会扑空；挂在左栏还有个副作用：左栏只有 264 宽，压根不是「右上角」。对话头里不再放任何图标，只留「‹ 返回」（窄屏）。
- **弹层没有遮罩，点到面板外面就收起**：它不是模态框，只是从底边升起来的一层，页面照常可见可滚——正因为底下那半页仍然可点，人在那种状态下按页面就是在说「我看完了」，不该再要求他去右上角找 `⌄`。三路关掉：右上角的 `⌄`、Esc、点面板外任意处（监听 `mousedown` 而不是 `click`，按下即收，免得拖选文字时先收起一半）。**没有遮罩，所以这三路必须各自都在**：少一路，那半页就成了「点了会误触进去却关不掉」的陷阱。
- **窄屏只有一个切换类 `is-thread`**：面板不加 `is-thread` → 只显示左栏（会话列表铺满）；加了 → 只显示右栏（对话铺满，对话头出现「‹」返回）。不要写成「默认留左栏 + 反过来加类显示左栏」那种双向开关，两个方向的默认值会打架。宽度只由一条公式算：`min(1313px, 100vw − 64px)`，窄屏不再另设（`@media (max-width: 899px)` 只管切单栏）；`prefers-reduced-motion` 下关掉升起动画。
- **输入框的 40 / 88 是局部口径，不是全局控件口径**：外壳里 `textarea` 的公共规格是「最小高 120、内距 10/12」（`base.html:429`），协作室的输入框必须显式压回 24 行盒起步——`min-height: 24px`，超过一行往上长，到 88（三行）封顶后内部滚动。发送按钮与输入框**垂直居中**，靠 `align-items: center` + 1px 上下内距 + 36 圆按钮凑出 40 高；写成 `flex-end` 时按钮会掉到底边。
- **消息贴输入框排，不贴顶**：一两条消息时消息区顶部会露出一大片空白（消息贴底排）。CSS 侧用一条 `flex: 0 0 auto; margin-top: auto` 的伪元素占位顶上去，别用 `justify-content: flex-end`——内容超高时 `flex-end` 会把顶部裁掉、滚不到最早的消息。打开会话即滚到底，切会话也滚到底。
- **「加载更早」是替换那一行，不是重画整个消息区**：加载行自带 `id="collab-before"`、`hx-target="this"`、`hx-swap="outerHTML"`，历史消息 prepend 在它下面；`htmx:beforeSwap` 记下 `{scrollTop, scrollHeight}`，`afterSwap` 按高度差把 `scrollTop` 补回去，视线原来那条不被顶走。滚到顶自动触发（`scroll` 不冒泡，监听要挂 `capture`），全部拉完后加载行换成「已经是最早的消息了」并不可再点。
- **开合状态挂在 `<body>` 上，不能挂在 htmx 的 swap 目标上**：`#collab-host` 是 htmx 的替换目标，htmx 会改它的 `className`（`htmx-settling`），挂在上面的 `is-open` 会被抹掉，面板升不起来 / 升起来关不掉。规则：`body.collab-open` 控制升起，脚本里用`wantOpen` 一个变量做唯一真相（`reveal()` 读它、`close()` 清它），按钮与 Esc 都只改它。

### 6.1 窄档表格（≤1100px）：带控件的表拆块、只读表折行（2026-11-01 定）

**先分三态，别一起改。** 拆块只挂在 `.wh-table-controls` 这一层，而它由 `modules/table.html` 的 `{% if inline_widgets() %}` 决定——`inline_widgets()` 判的是 `_state().mode in INLINE_MODES`，`INLINE_MODES = ("edit", "preview")`（`app/oams/render.py:52`）。所以：**`edit` 套、`preview` 也套、`readonly` 不套**。换句话说，「只读表不套」这句得说准：这里说的「只读表」是 **readonly 态**（`render_read_only()`，`render.py:987`）——它靠 `td` 折行本来就装得下（同一批 5 列数据实测行高 31→49、无截断），**readonly 一个字都没改**；而 **`preview` 态会套**（`render_preview()` 也走 `inline_widgets()`，审核侧的模块预览片同一条路），所以在 ≤1100 下审核预览片也是拆块排布——**那不是回归**，窄栏里拆块本来就比五列挤着好读。

- **带控件的表（`edit` / `preview`）≤1100px：每条记录拆一块。** 一行记录变成「标签在上、控件在下」的一列：`tr` 改 `display:flex; flex-direction:column`；记录与记录之间 `16px` + 1px `--oams-line` 分隔线，字段与字段之间 `12px`，标签↔控件 `8px`；控件撑满整行宽（实测 768 下 543、1024 下 767，此前一律被压成 320）。表头 `display:none`，列名用 `td::before { content: attr(data-label) }` 回显（12/16、`--oams-muted`）——**信息不丢，只是不再单独占一行**。不给记录加圆角：模块自身是 18 圆角 + 内距 16，里面再套一层会把角咬掉，也算不出令牌值。**为什么不是横滚**：坏的是填报表单，一边横滚一边填会丢行；横滚留给只读宽表。
- **必须拿掉外壳那条 320。** `base.html` 给页面数据表写的 `white-space:nowrap + overflow:hidden + text-overflow:ellipsis + max-width:320px`（§7 第 6 条）在窄档照样命中，它按「宽表每列 320」的容差算，会把拆块后本该整宽的一格仍限成 320——值一长就又被裁掉，等于换个门槛重来。窄档里这一段显式写 `max-width:none; white-space:normal; overflow:visible; text-overflow:clip`。
- **断点为什么是 1100，不是 900。** 一盏格要放下一句常见中文值至少 **132px**：8 个汉字 × 13px ≈ 104 + 左右内距 24 + 边框 2 = 130，取 132 留 2px 亚像素余量。本页最长值「差旅报销 2026-11-01」实测要 **181px**，五列合计 905；而 1024 档容器只有 801。断点若放到 900，1024 仍会把科目最后 5px 裁掉——「窄档不许裁字」当场破。所以从 1100 起就拆，1024 也在内。

- **多行表单只预填第 1 行**（2026-11-01 定，`171ced5`）：`table` 模块按 `rows` 连画多行「填新记录」空行，而这些行共用同一份 values——不区分的话每行都拿到上一条（真机实测 5 行同值，人以为已经存了 5 条，再点一次提交又多一条）。做法：`app/oams/render.py` 的 `input_for_key(..., prefill=False)` 只留 placeholder，`modules/table.html` 传 `prefill=(row == 0)`。行数上限 5、必填只卡主记录字段这两条不变；`edit` 与 `preview` 一致（预览片就是「这页长什么样」，5 行都塞样例反而让人以为这页预置了 5 条数据）。
- **第 1 行只带「辨识信息」，日期与金额故意留空**（2026-11-01 负责人拍板，**是口径不是缺陷，别当 bug 报、别顺手补**）：`_interface_values()`（`app/oams/web.py:449`）只回填 `title / status / note / evidence / display_only` 这几类 `map_to`；`date`（`map_to completed_at`）与 `amount`（落 `extra`）不回填。理由不是漏了：**科目、凭证号、状态是「这条归到哪」的辨识信息，带过来省事；金额与日期是这一笔的实质内容**——带上一笔的值，人扫一眼就点提交，账上就多一笔错的。空着逼人填一次，成本低得多。**缺数据让人停一下，比错数据混过去好。**

**列分级（C 方案，只落规则、暂不落代码；6 列以上的只读宽表才用，今天一张都不改）**：

| 级别 | 哪些列 | 处理 |
|---|---|---|
| 必留 | 唯一识别列（单号 / 编号）、汇总列（金额 / 数量）、状态列、标题列 | 原样保留 |
| 可折 | 日期、备注、经办人 | 折成标题列下一行小字（12/16、`--oams-muted`），不再单占一列 |
| 可去 | 派生列（能由其它列算出，或与其它列重复表达） | 窄档直接去掉 |

**什么时候允许横滚**：只有「只读宽表 + 按上表降列仍压不住」才滚，而且**只滚容器、不滚页面**（`overflow-x:auto` 落在模块内），滚动条必须可见——macOS 默认不滚不显示，得配可见滚动条或明确的滑动提示，否则等于把数据藏在屏幕外；页面 `scrollWidth === clientWidth` 必须成立。**录入态不许横滚。**

**验收口径（改这类表照这六条量）**：① 三档 1440/1024/768 页面 `scrollWidth === clientWidth`；② 控件不裁字（`input` 判 `scrollWidth > clientWidth + 1`；`select` 按最长选项量字宽 + 左右内距 + 24 箭头区，与控件宽比）；③ 页面上不出现 `…` 或「请选…」当显示值；④ 1440 视觉与改前一致（财务报销表 1183 / 容器 1217）；⑤ 768 下真填一行真提交（303 + `?saved=1`、条目 +1，验完删掉新增条目）；⑥ 越界元素为 0（排除 `position:fixed` 与祖先是滚动容器的）。

**落地位置**：`app/oams/templates/modules/table.html`（`td` 加 `data-label`，`section` 在 `inline_widgets()` 为真时加 `wh-table-controls`）+ `app/oams/static/oams-modules.css` 末尾的 `@media (max-width: 1100px)`。**`inline_widgets()` 覆盖的是 `INLINE_MODES = ("edit", "preview")` 两个模式**（`render.py:52`），不是只管填报表单页——所以改这一段 CSS 时，`edit`（填报页与工作台孪生页）和 `preview`（审核侧预览片、MCP 的 `preview_descriptor` → `mcp/tools.py:563`、`plugin_cli.py:137`）一起变，`readonly` 不动。排查与取舍过程见 `docs/reports/20261102-narrow-table-audit.md`（2026-11-01 随目录拆分移入内部仓 `oams-records`，主仓不再有）。

> 分层判断：**骨架层** = 页面外壳（一页一套，全站复用）；**组件层** = 卡片 / 面板内部用的控件与数据件；**浮层** = 浮在整页之上的东西；**协作室** = 右下角圆按钮呼出的全局讨论层；**模块层** = 与 `MODULE_REGISTRY` 对齐、由容器 + 组件拼成的内容块。新组件先判断属于哪一层，再进对应分区。

## 7. 八条硬规则

1. **只用令牌**：颜色、圆角、间距、字号一律引用变量/`--oams-*`，不写字面值。
2. **不发明圆角**：五档里挑一个 —— 方框 4、行与高亮 9、中等块 18（含输入框 / 下拉 / 文本域）、容器 26、胶囊 999；表格本体 0。挑不到就说明该加组件，别加圆角。
3. **内容实色、浮层玻璃**：页面里的卡片 / 表格 / 面板靠底色差与 1px `border/default` 分层，**不加投影、不加模糊**。凡是浮在内容之上的一层——顶栏胶囊（含静止态中间那颗导航胶囊）、账号菜单、开发模式身份菜单、下拉框展开层、Menu、Tooltip——一律「**本体玻璃**」，只有这一套：

 ```css
 /* 条状浮层：顶栏胶囊、导航胶囊 */
 background: rgba(255, 255, 255, .70);
 backdrop-filter: saturate(1.2) blur(10px);
 box-shadow: 0 4px 12px -2px rgba(15, 23, 42, .10); /* 唯一的投影，别加第二层 */

 /* 面板状浮层：菜单、下拉框展开层、Tooltip —— 白 78% + blur 16，比条状浮层更雾 */
 background: rgba(255, 255, 255, .78);
 backdrop-filter: saturate(1.3) blur(16px);
 box-shadow: 0 4px 12px -2px rgba(15, 23, 42, .10);
 ```

 为什么面板比条状浮层更雾：菜单里要读字，底下正文必须退到雾里，否则两层文字叠在一起谁也读不清；顶栏只承载导航，看得见底下流动的内容才是它存在的意义。两者的投影**同一值**，只差粒度。

 **浮层不能长在 `<details>` 里**（2026-10-26 定，踩过）：账号菜单与身份菜单一度把面板塞在 `<details>` 内部，结果是「菜单透得比顶栏胶囊明显得多」。原因不在数值——`<details>` 是一个 backdrop root，里面的 `backdrop-filter` 只能采样这个 root 内部的绘制内容，拿不到页面背景，玻璃就退化成一层平白，底下的字照样清晰可读。同一份配方挂到 `<body>` 上立刻正常（同一块黑白条纹实测：`<details>` 里条纹残留 p2p 94，`<body>` 上 p2p 4）。所以浮层一律挂 `<body>`、`position: fixed`；触发器只负责「按一下」，面板挂在哪儿、摆在哪个坐标、什么时候收起来，全归**浮层载体** `static/wh-popover.js`（见下）。

 `<details>` 之外，也别把浮层塞进带 `transform` / `filter` / `opacity < 1` / `mask` 的容器：它们同样可能成为 backdrop root，玻璃就只剩一层白。

 **不落遮罩**（2026-10-26 定）：菜单和下拉框底下一度盖过一层 `rgba(10,10,10,.12)` 的薄雾，撤掉了——blur 已经把正文糊开，再压一层灰只会让整页发闷、面板显脏。代价是**「点到别处要关掉」得由脚本兜住**——这一条统一由载体做（document `mousedown` / `Esc` / `focusout` / `scroll` / `resize` 五路），加新浮层不用重写一遍，但**也别把这几路监听删掉**，删了就没有遮罩替你收尾。将来的 Modal 要不要遮罩，等真做时单独定，不要顺手抄菜单。

 圆角按位置取：条状浮层（顶栏胶囊、导航胶囊、徽标胶囊）用 `radius/pill`；面板状浮层分两种——**挂在外壳上的**（账号菜单、开发模式菜单、弹窗、Tooltip）用 `radius/card` 26，**从卡片里的控件拉出来的**（下拉框展开层、卡片行内的 `…` 菜单）用 `radius/control` 18：外层卡片已经占了 26，同一处不重复用容器档（同 §3 的嵌套规则）。浮层不加描边——投影 + 明度差已经够分离，再描边会在玻璃上出现一道硬线。

 上面这些值和 `backdrop-filter` 是**唯一允许写字面值的地方**：玻璃是「叠在什么上面」的效果，不是一种颜色，进不了颜色令牌。要改就几处一起改（见 §8.3 的落点清单），别只改一处。

 **浮层只有一个载体**（2026-10-26 定）：三处浮层原先各写各的——顶栏胶囊是纯 CSS，账号菜单与身份菜单是一段 `wireMenu()`，下拉框是 `wh-select.js` 自带的定位。外观统一了，但**挂载 / 摆放 / 关闭**三件事各做了一遍，加第四个浮层就得抄第四遍。现在只有 `static/wh-popover.js`：

 - **声明式**：触发器写 `data-wh-popover` + `aria-controls="<面板 id>"`，面板写 `class="wh-popover"`。可选用 `data-wh-align`（start/end）/ `data-wh-side`（below/above/auto）/ `data-wh-gap` / `data-wh-min-width` 调位置。载体自动把面板 append 到 `<body>`、置 `hidden`、维护 `aria-expanded`、按视口夹取坐标（8px 边距、下方不够翻上方），htmx 换完内容自动重扫。
 - **长相只有一条规则**：`.wh-popover`（玻璃 + 28 圆角 + 唯一投影 + `--z-popover: 70`）。`.account-menu` / `.dev-menu` / `.wh-list` 只声明宽度与内距，**不许再写 background / box-shadow / backdrop-filter**。
 - **要自己管开关的**（比如下拉框按需构建选项行）用 `whPopover.attach({... , manual: true})` 拿实例，其余一律声明式。
 - **契约有测试**：`tests/test_popover_contract.py` 盯着这条——面板跑进 `<details>`、皮肤被抄第二遍、`wh-popover.js` 下到 `wh-select.js` 后面，都会红。

 目前的落点：顶栏（滚动后的窄胶囊；静止态下玻璃在中间的导航胶囊上，条形本身透明；玻璃做在 `.bar-glass` 这一层上，因为带 `backdrop-filter` 的元素会成为 backdrop root，嵌在里面的下拉就取不到页面背景）、账号菜单 `.account-menu`、开发模式身份菜单 `.dev-menu`、下拉框展开层 `.wh-list`。以后加 Modal / Tooltip / Popover 不要另调一套数值——直接照抄上面，再把新落点补进 §8.3。没有描边的实色面板之间必须留 `space/5`（16px）——两块白面板贴在一起会粘成一整块，26 的圆角还会互相啃出缺口。
4. **一个强调色**：`accent/default` 一屏只出现一次主动作；次要动作走 `secondary`（白底 + hairline）。
5. **状态色只表达状态**：不许拿 `status/danger` 做装饰，也不许拿 `data/agent` 做品牌色。
6. **表格单行**：行高 30（6/8 内距 + 18 行盒 + 1px 分隔线），页面数据表的单元格不折行，超宽用省略号（`text-overflow: ellipsis`），不靠缩字号；模块内明细表在窄栏里可以折行。**窄档（≤1100px）以 §6.1 为准**：带控件的明细表拆块、不裁字，只读宽表才考虑降列或容器横滚。
7. **控件四态**：每个可交互组件都要有 default / hover / focus / disabled；表格行要 default / hover / selected。
8. **数字优先**：指标数值用 `Display/Metric`，单位小一号且 `text/muted`；金额与数量右对齐。

- **玻璃态的五个落点**（代码事实，改之前先确认）：顶栏 `header.topbar.is-scrolled .bar-glass`（720 胶囊，静止态透明）、静止态中间的 `.bar-nav` 胶囊、账号菜单 `.account-menu`、开发模式身份菜单 `.dev-menu`、下拉框展开层 `.wh-list`。前两处是条状档（70% 白 / blur 10），后三处是面板档（78% 白 / blur 16），投影全用同一值；档位混用会看出两种玻璃。圆角跟着出身走：账号菜单 / 开发菜单挂在外壳上取 26，下拉框展开层是卡片里拉出来的取 18。这三个面板都由 `static/wh-popover.js` 挂到 `<body>` 上（见 §7.3 的 backdrop root 那条），塞回 `<details>` 里玻璃就失效；面板皮肤只写在 `.wh-popover` 一条规则里，三个面板类只留宽度与内距。**没有遮罩**：透明到能看见底下内容但不该盖一层灰，浮层靠 blur 与投影分离。
- `--r-sm`（=微 4）与 `--r-lg`（=小控件 9）是历史别名，新代码直接用 `--r-micro` / `--r-small`。
- `radius/md`(8)、`radius/xl`(14) 留在令牌表里但不再使用。
- **表格单元格内联编辑框高 28，不算破「控件 30」**（2026-10-30 定）：30 是标准控件基准线（`input` / `select` / `button` 独占一行时的行内高度）；表格里的内联编辑框是**单元格内元素**，不是标准控件，跟着 30 行高走（行盒 30、框 28、上下各 1 留白），无边框、聚焦才描边。别把它当破例去凑 30，也别把这个 28 挪到表格外面用。
- **preview（审核视角）渲染 disabled 控件，不是静态文本**（2026-10-30 定）：审核审的是这页的**定义**——能不能填、填完什么形状，所以 preview 走 `INLINE_MODES = ("edit", "preview")`，控件在场但 `disabled tabindex="-1"`，值用样例数据；`readonly`（上级看结果）才降级成 `.wh-field-static` 纯文本。旧的「preview 不许出现控件」口径与 `render.py:51` 的常量互相矛盾，已按本条统一。

- **模块层样式表从来没被加载（2026-10-26 修）**：`static/oams-modules.css`（662 行，模块层全部规格）此前没有任何模板引用它——部门界面渲染出的 `wh-m / wh-input / wh-table` 在浏览器里一条规则都没生效（实测：外壳 radius 0、padding 0，真控件被外壳的 `input` 规则预制成 9/12）。现在在 `base.html` 的 `<head>` 里、内联 `<style>` 之前挂 `<link rel="stylesheet" href="/static/oams-modules.css">`：模块层先落，外壳的同名规则后落，冲突以外壳为准。
