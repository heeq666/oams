# AI 化公司看板：提案评估

日期：2026-10-09
状态：**定位仍冻结**。本文记录对"AI 原生看板"方向的第一轮评估，以及如果要走，必须满足的前提。

## 1. 提案原文（摘要）

各部门都用 AI 工作，所以 Workhub 不该做成传统 ERP 或多维表看板。设计要点：

- 既支持传统填报查看，也支持 AI agent 操作
- 核心是**建立规则给 AI**，AI 读规则就知道怎么在本项目里搭看板
- AI 同时理解用户需求，决定用什么方式搭
- 固定数据由各部门自己设定时任务上传
- 提供产品卡、进度栏、成员卡等**预设模块**提高搭建效率
- 目标：全部门用 AI 从 0 到 1 协调，也支持日常工作

## 2. 评估：一个真东西，两个幻觉

### 2.1 真东西：定时数据接入

看板类系统失败的唯一原因不是"搭不出来"，是**没人维护**。飞书多维表格、Notion、钉钉项目都死在这。

让各部门自己设定时任务喂数据、AI 只负责归一化和字段映射，是**直接打在痛点上**的做法。这是整个提案里唯一有独占价值的部分，也是唯一值得在第一版做的。

### 2.2 幻觉一：AI 读规则搭看板

- 搭看板从来不是难点。飞书、Notion 的拖拽比跟 AI 对话更快
- AI 生成的布局**无人负责**。三个月后没人知道这个看板为什么长这样、口径是谁定的
- 这是把"可控的搭建"换成"不可控的搭建"，方向错了

### 2.3 幻觉二：预设模块提高效率

产品卡、进度栏、成员卡是**通用件**，每家看板工具都有。为它建组件库是几周工时换零差异化。别建。渲染层通用即可，AI 输出标准块规格，不要预设组件库。

## 3. 提案里被埋掉的关键洞察

提案说"建立规则给 AI"——方向对，但**规则的内容搞错了**。

规则不该描述"怎么摆卡片"，该描述"**谁是谁、谁能看什么、谁负责什么**"。

而这正是迁移 0001 已经建好的东西：稳定岗位 ID、有始有终的任职、限期代理与到期回收、权限授予、审计事件。

**这决定了 AI 能不能搭对，而不是搭得快不快。** 飞书的 AI 也能搭看板，但它搭不对——不是不会排版，是因为它的多维表格里不知道什么叫"岗位""代理""任期"。它不知道张三现在是否在替李四，不知道代理 2026-12-31 到期。

**Workhub 的独占价值 = 组织语义底座。** AI 读得到这套语义，搭出来的看板才是"谁负责什么"正确的看板。这是现成工具给不了的。

因此：**这不是推翻定位 A（岗位权限中台），这是给 A 加一层 AI 接口。**

## 4. 三层结构

```
呈现层   通用渲染 BoardSpec    进度栏 / 成员卡 / 产品卡 —— 通用件，不建组件库
   ↑
AI 层    受控写入              读规则 → 归一化 → 输出规格，每步进审计
   ↑
规则层   组织语义 · AI 只读    岗位 / 任职 / 权限 / 审计 —— 唯一壁垒
   ↑
接入     定时数据接入          各部门设定时任务，AI 做归一化映射
```

## 5. 三条硬边界（不设就毁系统）

1. **Agent 对岗位/任职/权限数据只读。** 绝不允许 AI 创建岗位、建立任职、发放授权——那会直接摧毁审计链，使"双签"和"代理 90 天上限"这两条已确认的业务决策形同虚设
2. **看板规格必须是声明式 JSON**（BoardSpec），可 diff、可回滚、可被人接管。AI 的输出物必须有人能读懂并手动修改
3. **AI 的每次写入进审计**，标 `actor_type='agent'` 及触发来源。否则出事追溯不到

## 6. 第一版不要做通用 agent

通用 agent 的基建成本（工具调用、沙箱、防跑偏、评测）比重写一遍 CRUD 还贵。

**第一版做固定 pipeline**：定时抓取 → AI 归一化映射 → 写入看板。AI 只干"归一化"这一件事，不干"决定怎么搭"。

## 7. 仍然必须先回答的三个问题

定位冻结没有解除。这三个问题没答案之前，不写代码。

1. **有没有部门真的有周期性数据愿意设定时任务？** 如果一个都没有，第 2.1 节这个最亮的点就是空的，整个提案失去独占价值
2. **第一个看板给谁看？** 只能选一个：管理层 / HR / 某个部门负责人
3. **数据从哪来？** 能不能自动取（数据库、API、文件共享），还是必须人填。必须人填的话，就退回"没人维护"的老问题，AI 救不了

## 8. 与既有资产的关系

| 既有资产 | 在新方向下的处置 |
|---|---|
| 迁移 0001（岗位/任职/权限/审计） | **保留，升格为"规则层"**，是 AI 的语义来源，AI 只读 |
| FastAPI 服务骨架 | 保留，需新增 BoardSpec 与 agent 审计字段 |
| 5 条已确认业务决策 | 继续有效，且正是 AI 需要读的规则内容 |
| 企业微信 OAuth | 仍阻塞于无可信域名；与 AI 方向无关，不影响本决策 |
| 行级数据范围过滤 | **优先级上升**。AI 代读数据后，行级过滤从"员工能不能看"变成"AI 能不能看"，缺了它 AI 会越权 |
