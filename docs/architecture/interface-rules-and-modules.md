# 界面规则与模块规范（协同底座约束层）

状态：**草案，待确认。** 本文件定义“部门界面可以由 AI 自由生成到什么程度”。它是整套系统的约束层，先于任何页面实现。

## 1. 定位

Workhub 不是一套固定表单，而是可进化的全公司协同底座。三层职责分离：

- **底座（本项目代码）**：身份、岗位、任职、权限、审计、数据模型、公司进度中心聚合、界面描述校验与渲染。
- **规则（本文件）**：任何部门界面都必须遵守的字段映射、模块和汇总契约。
- **Skill（AI 侧）**：教 AI 用素材库里的模块和术语，按规则帮各部门拼出界面，产出「界面描述」而非任意页面代码。

部门负责人用 Skill 让 AI 制作本部门界面；界面由底座渲染；数据回到统一的进度中心。

## 2. 字段规则：自定义允许，但必须映射

### 2.1 底座标准字段（不可绕过）

任何部门界面产生的每一条进度，最终必须落到这些字段，否则无法进入公司汇总：

| 标准字段 | 含义 | 是否必填 |
|---|---|---|
| `work_item_id` | 事项唯一标识 | 必填 |
| `title` | 事项名称 | 必填 |
| `org_unit_id` | 所属部门 | 必填 |
| `position_id` | 责任岗位 | 必填 |
| `status` | 标准状态：未开始 / 进行中 / 阻塞 / 已完成 | 必填 |
| `blocked_reason` | 卡在哪、在等谁 | 阻塞时必填 |
| `needs_decision` | 是否需要管理层拍板 | 默认否 |
| `progress_value` | 完成进度 0–100 | 可选 |
| `note` | 这次做了什么 | 必填 |
| `evidence` | 依据（能证明这句话的来源） | 必填 |
| `reported_at` / `updated_at` | 时间 | 系统生成 |
| `reported_by` / `submitted_via` | 提交人、提交渠道（人工/AI 代笔） | 系统生成 |

### 2.2 自定义字段

- 允许部门自定义字段，保留灵活性。
- **每个自定义字段必须显式声明映射**：`自定义名 → 标准字段或展示位`。
- 映射不上的字段：只能作为“展示型附加信息”存在，**不参与公司汇总、不参与排序筛选、不进入风险计算**，并在界面上标注「仅本部门可见」。
- Skill 在生成界面时必须要求作者给出映射；没有映射的字段不允许声明为“进度/状态/依据”。

### 2.3 自我进化机制（每日）

1. 底座每天扫描所有部门界面中的自定义字段与自定义模块。
2. **升级阈值：被 ≥2 个部门使用即进入候选。** 跨部门出现说明它已是跨部门共识，不必等待使用次数。
3. 生成**候选标准字段/候选标准模块提案**（含建议名称、类型、示例值、已使用的部门与事项）。
4. 提案进入公司审核队列。
5. 审核通过 → 升级为底座标准字段或标准模块，全公司可用，并进入素材库；未通过 → 保留为部门私有能力，继续观察。

这样既保留灵活性，又让真正通用的概念沉淀为底座能力，实现自我进化。

## 3. 模块库

AI 拼部门界面时，只能从这些模块里选（可组合、可排序），自定义模块必须映射到底层模块。

> 本节的表回答「能选哪些模块」；每个模块长什么样、三视图（填报 / 只读 / preview）× 三状态（空 / 数据不全 / 有数据）各该出现什么文案、对应哪个 Figma 节点，以 [模块状态矩阵](module-state-matrix.md) 为准。矩阵 §2 是代码里 `MODULE_REGISTRY` 的 20 个 key，本节是概念层的模块库，两者粒度不同。

| 模块 | 作用 | 产出标准字段 |
|---|---|---|
| 事项卡 | 一条工作在推进中的事项 | title / position / status |
| 进展条 | 完成百分比或阶段 | progress_value |
| 阻塞卡 | 卡在哪、在等谁、等多久 | blocked_reason / status |
| 待决策卡 | 需要谁拍板、截止什么时候 | needs_decision |
| 依据输入 | 来源、时间、可查证 | evidence |
| 负责人块 | 责任岗位（不写死人名） | position_id |
| 时间线 | 历史汇报与变化 | reported_at |
| 指标卡 | 一个数值及其口径 | 自定义 → 映射展示位 |
| 清单块 | 批量条目（款号、SKU、场次等） | 自定义 → 映射展示位 |
| 附件/链接块 | 稿子、图片、单据 | evidence |
| 周期块 | 汇报频率与截止时间 | 展示位 |

### 3.1 自定义模块（可约束范围内）

默认模块库覆盖不到的场景，允许部门自定义模块，但必须在可约束范围内，不是任意代码。

允许：

- 组合已有模块形成复合块（例如「款号清单 + 进展条 + 依据」合成一个“打样进度块”）。
- 定义新的展示形态：表格、看板列、时间轴、分组标题、对照表等。
- 定义新的字段集合，只要每个字段都给出映射（见 2.2）。
- 定义本部门的计算展示（如售罄率用哪个分母），但必须写明口径并落到指标素材。

不允许（超出约束范围即拒绝渲染）：

- 执行任意脚本、调用外部接口、引入第三方依赖。
- 直连数据库、读写其他部门数据、绕过岗位数据范围。
- 覆盖或隐藏标准字段（事项、部门、岗位、状态、依据、时间、提交人）。
- 把未映射字段包装成可汇总的进度、状态或依据。
- 修改提交人、伪造时间、绕过必填校验。

自定义模块必须声明：模块名、用途、包含的字段与映射、展示形态、是否参与汇总、责任人岗位、示例一条。

升级路径：自定义模块被 ≥2 个部门使用后，进入候选标准模块提案，公司审核通过即升级为默认模块库的一员（见 2.3）。

## 4. 素材库分类

素材是 AI 制作界面时可复用的公司资产，公司统一维护，部门可申请增补。

1. **术语素材**：各部门名词表与同义词（例：款号、波段、样衣、投产、大货、返单、动销率、售罄率、场观、GMV）。
2. **指标素材**：指标定义与计算口径，避免同名不同算。
3. **依据素材**：可接受的依据类型清单与示例（样衣确认单、投产单号、大货入库单、直播后台数据、对账单、会议纪要、凭证号）。
4. **状态素材**：部门状态词 → 标准状态的映射表（如“打样中”→进行中，“等面料”→阻塞）。
5. **模板素材**：部门模板与公共模板。
6. **模块素材**：第 3 节的模块库及其参数，以及已审核通过的自定义模块。
7. **示例素材**：各部门的示例汇报话术与填写样例。
8. **规则素材**：校验规则（必填、长度、映射要求）。
9. **周期素材**：汇报频率与截止时间（日/周/波段/月）。
10. **视觉素材**：配色、图标、品牌规范。
11. **数据范围素材**：谁能看哪个范围，由岗位任职决定。

### 4.1 服装电商各部门示例（初稿，需各部门确认）

| 部门 | 典型事项 | 常用指标素材 | 常用依据素材 |
|---|---|---|---|
| 设计部 | 波段开发、款式设计、打样 | 款式完成数、打样数、改版次数 | 设计稿版本、版单、样衣确认单 |
| 视觉部 | 拍摄、素材制作、上架素材 | 拍摄批次、素材交付数 | 素材交付清单、拍摄排期 |
| 生产部 | 投产、大货、交期、返单 | 投产数、按期交货率、返单量 | 投产单号、大货入库单 |
| 新媒体部 | 内容发布、账号运营 | 发布数、互动量 | 发布链接、后台数据 |
| 直播部 | 直播场次、转化 | 场次、场观、GMV、转化率 | 平台后台数据、场次编号 |
| 商品部 | SKU 运营、补货、售罄 | 动销率、售罄率、库存周转 | 商品报表、补货单 |
| 商务部 | 渠道、活动、回款 | 销售额、回款额、活动场次 | 合同、对账单 |
| 仓储部 | 入库、出库、盘点 | 出库单量、库存差异率 | 出入库单、盘点表 |
| 人资部 | 招聘、入离职、培训 | 到岗数、在编数、离职率 | offer、入职记录 |
| 财务部 | 预算、成本、结算 | 预算执行率、成本、回款 | 凭证号、报表 |
| 总经办 | 跨部门里程碑、决策 | 里程碑达成率 | 会议纪要、决议编号 |

## 5. 模板治理

- **部门内部模板**：部门自己 fork 后修改，不需要公司审批，只在部门内生效。
- **公共模板**：必须提交公司审核，通过后才成为公共模板，其他部门可复用。
- 审核检查项：字段是否映射标准字段、状态词是否有映射、依据是否可查证、是否越权访问其他部门数据。
- 模板需记录来源（fork 自哪个模板）、版本、审核人与生效时间，便于回溯。

## 6. Skill 的硬约束

AI 在帮部门制作界面时必须遵守，写进 Skill：

1. 先读本文件的标准字段与模块库，不得凭空发明字段含义。
2. 自定义字段必须给映射；无法映射的标注「仅本部门可见，不参与汇总」。
3. 自定义模块必须在 3.1 的允许范围内：可组合、可换展示形态、可加字段，但不得执行脚本、不得直连数据、不得覆盖标准字段。
4. 部门状态词必须映射到标准状态。
5. 依据必须可查证：来源 + 时间，不得主观描述。
6. 责任人写岗位不写死人名。
7. 不得生成绕过底座校验的页面代码或直连数据库/API 的凭证。
8. 未确认的事实不得写入真实汇报。

## 7. 已确认与待定

已确认：

- 界面描述采用受约束的 JSON Schema，AI 产出描述、底座校验后渲染，不产出任意页面代码。
- 进化阈值：自定义字段或自定义模块被 **≥2 个部门使用** 即进入候选提案，代表跨部门共识。
- 允许在约束范围内自定义模块，不满足约束的模块拒绝渲染。

待定：

- 界面描述 JSON Schema 的字段级细节：已有草案，见 [界面描述格式](interface-descriptor-schema.md)。
- 每日进化任务的技术实现与扫描范围。
- 公共模板审核流程的系统载体（目前需人工）。
