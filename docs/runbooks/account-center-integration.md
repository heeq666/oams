# 独立账号中心接入契约（草案，尚未实现）

状态：准备清单，尚未实现账号中心适配器。

OAMS 后续不接入具体企业协作平台登录。认证由独立账号中心负责，OAMS 只接收经过验证的身份结果，并继续负责内部成员、岗位、任职、业务权限、数据范围和审计。

## 账号中心必须提供

在开始写适配代码前，账号中心负责人需要确认：

1. 认证协议：授权码、OIDC、签名令牌或其他正式方式；明确服务端如何验证，不把客户端传来的未验证身份字段当作登录结果。
2. 稳定身份：租户 ID、主体 ID、显示名称和账号状态的字段定义；主体 ID 不因改名而变化。
3. 状态同步：账号停用、恢复、合并和解绑如何通知 OAMS，以及 OAMS 最长多久必须撤销已有会话。
4. 密钥安全：签名密钥或服务端凭据的存放、轮换、过期和应急撤销责任人。
5. 回调安全：HTTPS、允许的回调地址、state/nonce 防重放、错误返回和登出行为。
6. 测试环境：测试租户、测试账号、重复绑定/未知账号/停用账号案例和回滚联系人。

## OAMS 映射规则

- 账号中心主体只能映射到已有的 workforce_members，未知主体进入待绑定状态，不自动创建岗位和权限。
- 一个有效外部身份映射由 provider + tenant_id + subject_id 唯一确定；解绑保留历史记录。
- 部门或职位属性只作为匹配线索，不能直接授予工作项权限。
- 每次访问仍由 OAMS 根据有效岗位任职计算权限和数据范围。
- 账号停用、离职、调岗或撤权后，OAMS 必须拒绝旧会话或递增令牌版本。
- 账号中心接入不能绕过现有的 CSRF、岗位范围、审计和敏感数据控制。

## 验收条件

适配器完成后，至少用测试账号验证：

- 正常登录能映射到正确成员并建立 OAMS 会话；
- 未知主体不能自动获得岗位权限；
- 重复主体映射被拒绝并留下审计；
- 停用账号的旧会话在约定时限内失效；
- 调岗后旧部门数据不可见、新部门权限按任职生效；
- 账号中心异常、签名错误、重放请求和回调错误不会建立会话。

在这份契约正式确认前，继续使用受控运维命令签发短时令牌，不在 .env 中添加猜测性的账号中心 URL、客户端 ID 或密钥配置。
