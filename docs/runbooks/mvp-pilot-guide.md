# OAMS 小范围真实试用操作说明

本说明给项目负责人使用，不要求懂代码。当前版本已经通过虚构数据技术测试和第一轮真人可用性测试；真实试用仍应从一个部门、少量非敏感事项开始。

## 1. 第一批准备什么

建议选择 1 个部门、1 名部门负责人、1 名公司管理者，试用 5 个工作日。只建立 3–5 条正在推进的工作事项，不要一次录入全部历史工作。

每条事项只准备：

- 事项名称，例如“10 月招聘计划”；
- 负责岗位，例如“人事经理”；
- 当前状态：未开始、进行中或阻塞；
- 如果阻塞，写明卡在哪里；
- 是否需要管理者决策。

试用期间可以填写工作进展和事实依据，但不要录入身份证号、薪酬明细、客户隐私、合同原件、密码、Token 或其他敏感附件。依据先写成不敏感的文字说明，例如“10 月 12 日招聘会议纪要”。

## 2. 账号从哪里来

当前版本没有用户名密码自助注册，也尚未接入独立账号中心。系统管理员登录后进入「设置 → 试用与开关」（地址 `/setup`），按顺序完成：

1. 建部门；
2. 建岗位；
3. 建成员并分配岗位，页面会同时授予该岗位的汇报权限，并生成一次性的登录链接；
4. 到「工作项」页面（`/admin/work-items`，左栏入口叫「工作项管理」）为该岗位建立 3–5 条不敏感事项。

登录链接只在结果页面显示一次，需要立即复制并私发本人。不要在群里发送，也不要多个试用者共用一条链接。

不要共享一个管理员账号给多人。每位试用者都必须有自己的成员和岗位任职记录，因为部门可见范围和汇报署名由任职关系决定。登录链接等同于临时密码；泄露、人员变动或试用结束后要让链接立刻失效：界面暂时没有「撤销会话」按钮，由运维把该成员状态改为停用（`PATCH /v1/members/<member_id>/status`，`employment_status` 写 `suspended` 或 `departed`），该成员的全部会话和登录链接当场作废。两个状态不完全一样：`suspended` 只作废会话和链接，岗位任职还在；`departed` 连岗位任职、授权一起结束。只是临时停一下就用 `suspended`，人走了才用 `departed`。

## 3. 两类人员怎么使用

### 部门负责人

登录后进入“部门汇报”。页面只显示本人当前任职岗位的未完成事项。负责人填写“这次做了什么”、可选进度和必填依据，核对后提交。即使文字由 AI/Skill 帮忙整理，负责人也必须核对事实；网页提交会记为人工提交。

### 公司管理者

登录后进入“进度中心”。明确的系统管理员可以看到公司汇总、各部门阻塞、待决策、未汇报和最近汇报；普通部门负责人只能看到自己当前任职部门。点击部门可以进入部门看板核对原始进展、依据、岗位和更新时间。

## 4. 第一天怎么检查

管理员完成账号和虚构预演后，再让真实人员操作：

1. 部门负责人确认页面中只有本部门、本人岗位事项；
2. 提交一条不敏感的真实进度和文字依据；
3. 管理者在进度中心找到该部门及最新汇报；
4. 双方核对事项、岗位、进度、依据和时间；
5. 尝试打开另一个部门的直接链接，普通负责人应被直接带到能看的页面（不弹 403 页，也不留提示条）。

任一步出现跨部门可见、人员署名错误或依据串项，立即停止录入真实数据，保留截图和发生时间并回到隔离测试库排查。

## 5. 五天试用怎么判断

每天只要求负责人更新真正发生变化的事项。第五天收集以下结果：

- 负责人是否能独立完成汇报；
- 管理者能否找到阻塞和待决策事项；
- 是否发生跨部门可见或错误署名；
- 与微信群、口头汇报或 Excel 相比，是否减少了重复追问；
- 哪个字段最容易看不懂或填错。

通过标准：没有数据越权；至少一条汇报帮助管理者看清阻塞、依据或作出安排；使用者不需要开发人员全程指导。未达到时先修改界面和流程，不扩大试用范围。

## 6. 当前明确限制

- 尚未接入独立账号中心，账号和临时登录链接需管理员在「试用与开关」页（`/setup`）创建；
- 当前部门范围依据成员的有效岗位任职关系，不是自由选择的部门；
- 公司级总览仅保留给拥有权限管理能力的系统管理员；
- 尚未完成并发提交、调岗/离职即时撤权、移动端和键盘无障碍专项测试；
- 「试用与开关」页会为所选岗位授予汇报所需的固定五条权限（`org_units` / `positions` / `work_items` 的 read，`reports` 的 read 与 submit），授权范围是全公司而非单个部门，暂不支持自定义权限组合；
- 登录链接、真实数据库和正式服务部署必须由受控管理员操作，不能把数据库暴露给浏览器或公网。
