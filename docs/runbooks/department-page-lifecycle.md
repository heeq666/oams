# 部门页面：制作、试填、审核、启用

面向部门负责人和公司审核人。说明一个页面从想法到正式使用的完整流程。

## 三步

```
部门制作并试填  →  提交审核  →  公司审核通过  →  正式启用
   (draft)          (pending)      (approve)      (active)
```

| 状态 | 谁能看到 | 能试填 | 数据去向 |
|---|---|---|---|
| 草稿（分页栏上标「待提交」） | 本部门 | 能 | 测试区，不进公司汇总 |
| 审核中 | 本部门 | 能 | 测试区，不进公司汇总 |
| 已启用 | 本部门 + 管理层 | 能 | **进入公司汇总** |
| 已归档 | 无人（历史保留） | 不能 | 历史 |

## 部门负责人怎么用

1. 打开「进度中心」（或「汇报中心」），在左侧选中自己的部门
2. 点分页栏最右的「＋ 新页面」
3. 把 AI 按公司规则产出的页面描述贴进去，保存（贴之前先跑一遍下文的「提交前自检」，能省一轮来回）
4. 新页面立刻出现在分页栏，带「待提交」徽标（点进去后页面顶部会写明「当前页面待提交审核」）
5. 点进去**试填**几条，看字段够不够、说法对不对
6. 满意后点「提交审核」
7. 审核期间还能继续试填；发现写错了可以点「撤回提交」退回上一步
8. 被退回时页面顶部会显示公司写的退回原因，改完再提交

## 提交前自检（离线，不连库）

页面描述在贴进 `/setup/interfaces` 之前，可以先在本机验一遍。三个子命令**全部离线**：不连数据库、不联网，只读你给的那个文件——所以随便跑，跑坏了也不影响任何数据。

```sh
.venv/bin/python -m oams.cli plugin check   <描述文件>            # 静态校验
.venv/bin/python -m oams.cli plugin preview <描述文件> --out /tmp/preview.html
.venv/bin/python -m oams.cli plugin upgrade <旧描述文件> --out /tmp/upgraded.yaml
```

- **check**：静态校验字段映射、状态映射、模块版本、容器深度。通过时输出「OK 通过。字段映射、状态映射、模块版本、容器深度都没问题。」，退出码 0；有问题会逐条列出来，先修这些再贴。加 `--json` 便于接编辑器与 CI。
- **preview**：本地渲染一份 HTML（用假数据），看一眼排版和字段对不对，不用起服务、不用建页面（产物怎么算「对」，见本节末尾）。
- **upgrade**：把 schema 0.1 的旧描述升到 0.2（含模块词汇表改写），并列出「需要人工确认」的条目——那些是机器拿不准、要人看一眼的。升完再跑一次 `check`。

### preview 的产物怎么算「对」

打开那份 HTML，看到这四样就算过：

1. **标题和各模块都在**——没有整块缺失，也没有「未识别模块」这类字样。
2. **控件是灰的、点不动**（每个控件带 `disabled`）——预览是给人看定义，不是给人填。
3. **字段里有假数据**，不是一片空白——空白说明字段映射没对上。
4. **汇总类模块没数据时显示「—」**，不是 `0`——显示 `0` 就是把「没填」说成了「零」。

**已知缺口，不是你的错**：产物是 HTML **片段**，里面没有 `<style>`，直接丢进浏览器看是裸的（没样式、排版散），得贴进现有页面才有样子。这块（清单 G16：preview 自带 token 外壳）已定下轮补，手册先按现状说——看到裸的就对了，别去找自己的配置问题。

描述文件支持 `.yaml` / `.yml` / `.json`。仓库里 `examples/` 下有能直接过校验的样本，可以先拿它试手：

```sh
.venv/bin/python -m oams.cli plugin check examples/production-dept.yaml
```

## 审核人怎么用

打开「页面审核」，看到所有待审核页面：

- **通过并启用**：该页面成为部门正式页面，之后填写的正式数据进入公司汇总
- **退回部门**：必须写原因，部门能看到

审核人需要 `workforce.interfaces/review` 权限。这是一个**独立权限**，可以按人或按岗位授予，不附带任何管理员能力。

为什么不用管理员权限：`workforce.grants/manage` 同时允许改授权、改成员状态。为了审核页面而交出管理员权限，等于把"能给任何人开任何权限"也交出去了。所以审核单独拆成一个资源。

当前授予情况：系统管理员岗位（建表时自动回填）+ 设计部负责人、设计部管理员岗位（种子数据后加）。全新安装也能自己开：`/setup` 建成员时勾「**他是这个部门的负责人，能审本部门的页面**」，授权当场写进去（模板 `setup.html`，后端 `app/oams/web.py:2551`）。要给别的部门开审核，加同一条 `workforce.interfaces/review` 授权即可。

**服务端管三件事**（同一个判断函数 `_review_refusal`，`app/oams/web.py:1527`）：① 身份：系统管理员放行一切（任何部门、任何阶段，**包括自己建或自己提交的页**）；部门负责人要 `workforce.interfaces/review` 且页面在**他所在的部门范围内**；公司终审另要 `review_company`。② 状态：页面必须还在 `pending`。③ **AI 代签**：接入方会话要两个条件同时成立——允许时勾了 `interfaces:review`，且它代表的那个人本人就够权限（缺一条回中文 403「这是接入方的动作，审核要人自己点」）。

2026-11-04 按老大的模型重划，旧的「作者回避」（不能签自己提交的页）与「部门没人签就平台兜底」（`_stands_in`）都删了：前者把系统管理员挡在自己那页外面（他当天点不动审核页就是这个），后者会让平台在自己没资格时替人盖章。所以现在**部门负责人能签自己提交的页**，审计记的是他自己。

## 两条硬规则

1. **试填永远不进公司汇总。** 靠数据库字段 `entry_mode`（`live` / `draft`）隔离，不是靠界面遮挡。页面没通过审核前，它产生的一切都是 `draft`。
2. **同一部门同一页面标识同时只能有一个启用版。** 通过新版会自动归档旧版，避免两个页面都声称是当前版本。

## 常见问题

**审核通过后，之前的试填记录会变成正式数据吗？**
不会。试填记录保持 `draft`，一直不进汇总。审核通过后新提交的记录才是 `live`。

**提交审核后发现写错了怎么办？**
点页面上的「撤回提交」，页面回到待提交审核状态，试填内容全部保留。撤回只在**审核还没给出意见**时可用；一旦审核人已经通过或退回，就得按审核意见修改后重新提交——已作出的决定不能被撤掉。

**部门成员看不到某个页面？**
页面只对所属部门和管理层可见。确认你的岗位任职在该部门。
