# 部门界面使用说明

面向部门负责人和管理员，说明部门界面是怎么来的、怎么用。

## 它是怎么来的

每个部门的界面不是系统预先画好的，而是**部门负责人用 AI 按公司规则制作**的。流程：

1. 负责人告诉 AI 本部门要汇报什么、现在用什么词；
2. AI 按《界面规则与模块规范》与 [P0 接口契约](../architecture/p0-interface-contract.md)（descriptor v0.2）产出**界面描述**（一份 JSON/YAML，说明用哪些模块、字段映射到哪个标准字段、状态词怎么对上）；
3. 两种落地方式任选：**MCP 通道**——AI 通过 `create_draft_plugin` / `patch_draft_module` / `set_field_mapping` / `set_status_map` 直接写草稿（AI 令牌只绑 `plugin:write:draft`，永远拿不到 `plugin:approve`；`submit_for_review` 必须人工确认），或**人工通道**——管理员在「界面制作」页把描述贴进去；
4. 底座先校验：字段有没有映射、状态词能不能对上、有没有夹带脚本，**不通过就拒绝启用并说明原因**；
5. 通过后，部门成员就能在「部门界面」页打开填写。

## 部门负责人怎么用

1. 打开「部门界面」，找到本部门的界面；
2. 填写本次进展和依据（依据要能查证：单号、文件名、会议纪要）；
3. 提交。标准字段会进入公司进度中心，管理层能看到。

只有本部门可见的字段会标注「本部门可见，不参与公司汇总」，它们不会出现在管理层视图里。

## 管理员怎么用

- **界面制作**（/setup/interfaces）：把 AI 产出的描述贴进来，校验并启用。同一部门同一界面重画会生成新版本，旧的自动归档。
- **汇报汇总**（/interfaces/board）：按部门查看最近一次汇报的标准字段——事项、状态、卡在哪、进度、依据、更新时间和提交人。
- 公共模板需要审核人和审核时间，系统会强制检查。

## 出错了怎么办

- 描述校验不通过：页面会列出全部原因，把原因连同描述一起交给 AI 修改。
- 状态词未映射：说明部门用了新说法。让 AI 在描述的 status_map 里补上映射（如「等面料」→阻塞）。
- 提交被拒：检查必填项；标记为阻塞时必须写清卡在哪、在等谁。

## 现在的边界

- 自定义字段不参与汇总；每晚扫描未被映射的字段和自定义模块，被 **2 个及以上部门**使用才进入候选标准提案。
- 部门内部模板可以自由修改；要变成全公司公共模板必须提交审核。
- 界面描述有两条落地通道：管理员在页面导入（人工），或 AI 通过 MCP 服务端写草稿（`app/oams/mcp/`，12 个工具：6 只读 + 6 草稿写入）。AI 通道写不出上架状态——上架必须人工在审核页点通过。
- 插件描述格式已升级到 v0.2（预设模块 + 容器两层 + 能力声明 + 指标绑定）。存量 v0.1 描述用 `oams plugin upgrade <file>` 自动升级，升级结果会列出需要人工确认的条目。
