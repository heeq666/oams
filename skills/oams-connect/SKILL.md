# 接入 OAMS

你在替一个真人做事。**OAMS 只认人，不认你**——票是他自己点「允许」才有的，你不能替他拿，也不该向他要密码。

## 0. 先跟用户确认两件事

- **站点地址**：形如 `http://127.0.0.1:8000`（问一句，别猜）。
- **要干哪种活**：决定申请哪些范围，范围写在后面对照表里。**能少勾就少勾**，人更愿意点「允许」。

## 1. 取码

```http
POST {base}/api/apps/codes
Content-Type: application/json

{"name": "WorkBuddy（我的助手）", "scopes": ["entries:read:dept"], "purpose": "替用户查看本部门填报条目"}
```

返回里有 `code`（6 位）、`connect_url`（给人点的地址）、`expires_at`（**10 分钟**有效）。

`name` 会原样显示在允许页上；**这是你自己报的名字，不是 OAMS 发的证书**，所以起个用户认得出的名字，别起「系统」「官方」这种。

## 2. 把链接和码交给用户

建议这样说：

> 请打开 {connect_url} ，确认一下名字和权限，然后点「允许」。码：{code}（10 分钟内有效）

**不要**这样：向用户要账号密码；自己试着去点那个页面；把码发到公开的地方。

## 3. 换票

```http
POST {base}/api/apps/token
Content-Type: application/json

{"code": "482913"}
```

拿到 `token`（短期）和 `expires_at`。**票只放你自己的本地配置里**，别打印到聊天、别提交进仓库。

## 4. 干活

所有请求都带：`Authorization: Bearer {token}`

| 想干什么 | 请求 |
| --- | --- |
| 读本部门条目 | `GET {base}/v1/interfaces/{interface_id}/entries` |
| 往页面里填报条目 | `POST {base}/v1/interfaces/{interface_id}/entries`，体是 `{"values": {字段: 值}}` |
| 新建草稿页面并送审 | `POST {base}/v1/interfaces`，体是完整 descriptor |

`interface_id` 从哪来：用户给你，或者你先按部门问用户要哪一页——**别自己编**。

## 范围对照表（申请时写英文键，页面上显示中文）

| scopes | 页面上显示 | 能做什么 |
| --- | --- | --- |
| `entries:read:dept` | 读本部门的填报条目 | 只能读 |
| `interfaces:draft` | 新建草稿页面并送审 | 只能建草稿、送审，不能直接上线 |
| `entries:write` | 往本部门页面里填报条目 | 能写条目 |

**默认一个写权限都不给**：没勾就是没给。

## 出错了怎么办

| 状态 | 含义 | 你该做什么 |
| --- | --- | --- |
| 401 | 票无效、过期，或者用户已经断开 | 重新从第 1 步取码，请用户再点一次 |
| 403 | 这个范围没被允许（例如只勾了读却去写） | **去请用户重新授权并勾上**，不要换个接口绕 |
| 409 | 这个码已经换过票了 | 码一次性，重新取 |
| 410 | 码过期了 | 重新取 |

## 三条硬规矩

1. **绝不向用户要密码**。OAMS 从不把密码交给任何应用。
2. **不替用户点「允许」**。那一下必须落在他自己的浏览器里。
3. **被拒绝就退回找用户**，不要自己找别的路——你替他做的事都记在他名下，审计里看得到是你的应用动的手。
